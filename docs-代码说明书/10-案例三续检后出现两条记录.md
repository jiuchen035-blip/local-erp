# 10 · 案例三：灭火器年检"续检"后出现两条记录

---

## 一、先给结论

**这不是代码坏了，是后端故意这么设计的：续检 = 新增一条记录，旧记录保留当历史。**

但这个设计没有在界面上说清楚，所以你看到的现象是：

```
续检前：  张三（工地）  已到期待检       ← 1 条
点续检 ↓
续检后：  张三（工地）  已到期待检       ← 旧的还在
          张三（工地）  正常             ← 新生成的一条
```

你以为"它没改成功，反而多了一条"，实际是"它按设计给你留了底"。

---

## 二、怎么 5 分钟确认（三个证据，任选其一）

### 证据 1：看续检后的提示文字（最快）

提示是：**"已续检，新记录下次年检 2027-09-12"**

注意"**新记录**"三个字。如果是更新原记录，提示不会带"新"字。
小程序的批量续检弹窗写得更直白：

> "为选中的 N 条**各生成一条续检新记录**（下次年检=今天+12个月，**旧记录保留**）"

### 证据 2：查数据库（最硬）

用 DB Browser 打开 `data/erp.db`：

```sql
SELECT id, customer_name, inspect_date, next_date, remark
FROM inspection
WHERE customer_name = '那个客户名';
```

会看到**两条**，新那条（id 更大）的 `remark` 写着 **`续检自#5`**（5 是旧记录 id）。

### 证据 3：看后端代码（铁证）

`controller/InspectionController.java` 第 144-168 行：

```java
/** 续检：复制原记录生成新一条，本次年检日期默认今天，周期+12个月 */
@PostMapping("/{id}/renew")
public Map<String, Object> renew(@PathVariable Long id, ...) {
    Inspection old = inspectionMapper.selectById(id);
    ...
    Inspection next = new Inspection();          // ← 新建一个对象
    next.setCustomerName(old.getCustomerName()); // ← 把旧记录字段一个个抄过来
    next.setInspectDate(date);
    next.setNextDate(defaultNext(date));         // ← 下次日期 = 今天 + 12 个月
    next.setRemark("续检自#" + old.getId());     // ← 留线索
    inspectionMapper.insert(next);               // ★ 第 166 行：insert，不是 update
    return Map.of("message", "已续检，新记录下次年检 " + next.getNextDate(), ...);
}
```

**第 166 行是 `insert(next)`，全程没动过 `old`。** 一眼确认。

---

## 三、两个必须先知道的前置知识

### 1. "状态"不存在数据库里，是当场算的

`inspection` 表里**没有 status 这一列**。状态在每次查询时算（第 30-41 行）：

```java
public static String statusOf(Inspection i, int dueDays) {
    LocalDate next = LocalDate.parse(i.getNextDate(), D);
    LocalDate today = LocalDate.now();
    if (next.isBefore(today)) return "OVERDUE";                   // 已到期待检
    if (!next.isAfter(today.plusDays(dueDays))) return "DUE";     // 即将到期（默认30天内）
    return "NORMAL";                                               // 正常
}
```

**所以"变正常"的唯一办法就是把 `next_date` 推到一年后，没有别的开关。**

### 2. 统计数字也会跟着不对（你肯定觉得这点最别扭）

列表接口数"已到期/即将到期/正常"时，是对**全部记录**数的（第 64-66 行）。
所以续检之后：

| 指标 | 续检前 | 续检后 |
|---|---|---|
| 总数 | 1 | **2** |
| 已到期待检 | 1 | **1（旧记录还在，没降！）** |
| 正常 | 0 | 1 |

**"我都续检了，怎么待检还是 1"** —— 原因就在这。

---

## 四、怎么改：两种方案选一个

### 方案 A：续检 = 直接更新原记录（最快，5 分钟）

**适合**：只想要"点一下就变正常，别多出来一条"，不在乎历次年检历史。

整段替换 `InspectionController.java` 的 `renew` 方法：

```java
/** 续检：直接更新原记录（本次年检日期=指定日期，下次=+12个月），不产生新记录 */
@PostMapping("/{id}/renew")
public Map<String, Object> renew(@PathVariable Long id, @RequestBody(required = false) Map<String, String> body) {
    Inspection old = inspectionMapper.selectById(id);
    if (old == null) throw new IllegalArgumentException("记录不存在");
    String date = (body != null && body.get("date") != null && !body.get("date").isBlank())
            ? body.get("date") : LocalDate.now().format(D);

    old.setInspectDate(date);
    old.setNextDate(defaultNext(date));
    // 续检痕迹记在备注里，至少还看得出检过几次
    old.setRemark((old.getRemark() == null ? "" : old.getRemark() + " | ") + "续检于" + date);
    inspectionMapper.updateById(old);                    // ★ update，不是 insert
    return Map.of("message", "已续检，下次年检 " + old.getNextDate(), "id", old.getId());
}
```

**效果**：点续检 → 还是一条 → 立刻变"正常" → 待检数减 1。
**代价**：历次年检历史没了（只知道最后一次，不知道以前检过几次）。

---

### 方案 B：保留历史，但列表只显示最新那条（推荐）

**适合**：年检记录要留档（和"冲正不删原单"一个道理），既要界面清爽又要留底。

思路：给旧记录打"已归档"标记，列表默认不显示它。

#### 第 1 步：加字段

`resources/schema.sql` 的 `inspection` 表加一列：

```sql
archived  INTEGER NOT NULL DEFAULT 0,   -- 1=已被续检取代（历史），列表默认不显示
```

#### 第 2 步：让老库也升级（**别漏！**）

`config/MigrationConfig.java`：

```java
try { jdbc.execute("ALTER TABLE inspection ADD COLUMN archived INTEGER NOT NULL DEFAULT 0"); } catch (Exception ignored) {}
```

#### 第 3 步：Entity 加字段

`entity/Inspection.java`：

```java
private Integer archived;      // 1=归档（历史）
```

#### 第 4 步：续检时把旧的归档

`renew` 方法末尾改成：

```java
    next.setRemark("续检自#" + old.getId());
    next.setCreatedBy(user());
    next.setTotalAmount(round2(nzInt(next.getQuantity(), 1) * nzD(next.getPrice())));
    inspectionMapper.insert(next);

    old.setArchived(1);                    // ★ 旧的收进历史
    inspectionMapper.updateById(old);
    return Map.of("message", "已续检，新记录下次年检 " + next.getNextDate(), "id", next.getId());
```

#### 第 5 步：列表只统计未归档的（关键）

`list()` 第 58-59 行改成：

```java
List<Inspection> all = inspectionMapper.selectList(
        new LambdaQueryWrapper<Inspection>().orderByAsc(Inspection::getNextDate))
        .stream()
        .filter(i -> i.getArchived() == null || i.getArchived() == 0)   // ★ 过滤掉历史
        .toList();
```

`due-list` 第 99-100 行**同样加这个 `.filter(...)`**，否则催检名单里还会出现已经续检过的客户。

> **这个方案的好处：前端和小程序一行都不用改** —— 过滤在后端做，两端拿到的列表天然只有最新那条。

**效果**：点续检 → 界面还是一条、而且是"正常"，待检数减 1；
数据库里上一期记录完整保留（想查历史时把过滤去掉就行）。

## 五、已经产生的重复数据怎么清理

不管选哪个方案，之前续检产生的重复记录还在库里。**清之前先复制一份 `data` 文件夹。**

### 第 1 步：先看重复情况（只看不动）

```sql
SELECT customer_name, phone, COUNT(*) AS 条数,
       GROUP_CONCAT(id) AS ids, GROUP_CONCAT(next_date) AS 到期日
FROM inspection
GROUP BY customer_name, phone
HAVING 条数 > 1;
```

### 第 2 步：确认后清理

**方案 B（已有 archived 字段）—— 归档，安全可逆：**

```sql
UPDATE inspection SET archived = 1
WHERE id IN (
  SELECT id FROM inspection i
  WHERE EXISTS (SELECT 1 FROM inspection j
                WHERE j.customer_name = i.customer_name
                  AND IFNULL(j.phone,'') = IFNULL(i.phone,'')
                  AND j.id > i.id)          -- 保留 id 最大（最新）的那条
);
```

**方案 A（无 archived 字段）—— 只能删，先备份：**

```sql
DELETE FROM inspection
WHERE id IN (
  SELECT id FROM inspection i
  WHERE EXISTS (SELECT 1 FROM inspection j
                WHERE j.customer_name = i.customer_name
                  AND IFNULL(j.phone,'') = IFNULL(i.phone,'')
                  AND j.id > i.id)
);
```

> ⚠️ `DELETE` 不可恢复。执行前一定先复制 `backend/data/erp.db`。

## 六、验证（两方案通用）

1. 重启后端 —— 看启动日志有没有 `no such column: archived`，有就是漏了第 2 步
2. 找一个"已到期待检"的客户 → 点续检
3. 应该看到：**还是一条，状态变"正常"，下次年检 = 今天 + 1 年**
4. 顶部统计：总数不变、"已到期待检"减 1、"正常"加 1
5. 再用上面的 SQL 查这个客户：方案 A 只剩 1 条；方案 B 有 2 条但旧的 `archived=1`

## 七、一句话总结

| 现象 | 实际原因 | 修复 |
|---|---|---|
| 续检后一个客户出现两条，一条待检一条正常 | `InspectionController.renew` 第 166 行是 `insert`，**复制新增而不更新原记录**，旧记录留作历史 | 方案 A：改成 `update` 原记录（最快）；方案 B：加 `archived` 字段 + 列表过滤（推荐，留档） |

> 通用经验：**"点了个操作，结果多出一条" → 去后端找 `insert`，99% 是新增而非更新；
> "点了没变化" → 反过来去找 `update`。**
