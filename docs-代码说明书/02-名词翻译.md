# 02 · 名词翻译：代码里的符号到底是什么意思

> 这章不讲故事，只做一件事：**把你在代码里看到的每一个奇怪符号，翻译成人话。**
> 你可以把它当字典用，看到不懂的就回来查。

---

## 一、先搞清楚一个 Java 文件长什么样

打开任意一个后端文件，比如 `backend/src/main/java/com/local/erp/service/BillService.java`，结构是固定的：

```java
package com.local.erp.service;        // ① 这个文件住在哪个"文件夹"里

import 一堆东西;                       // ② 我要用到别人家的工具，先声明

/** ... 这是一段说明文字，不参与运行 ... */   // ③ 注释，写给人类看的

@Service                              // ④ 注解（后面讲）
@RequiredArgsConstructor
public class BillService {            // ⑤ 这是一个叫 BillService 的"盒子"

    private final BillMapper billMapper;   // ⑥ 盒子里面放的东西（别的类的实例）

    public Bill post(Long billId) { ... }  // ⑦ 盒子能做的事（方法）
}
```

用现实比喻：

- **class（类）** = 一个盒子，里面装着数据和能做事情的函数
- **方法** = 这个盒子能提供的服务。比如 `post(单据id)` 就是"给我一个单号，我帮你过账"
- **package（包）** = 文件夹。团队约定把同类的盒子放一起：`controller`（接待）、`service`（干活）、`entity`（数据）

## 二、后端最核心的比喻：一家餐厅

这是理解整个后端的关键。请记住这张表：

| 餐厅里的角色 | 代码里的名字 | 它负责什么 | 它的规矩 |
|---|---|---|---|
| **服务员** | `Controller` | 接待客人（接收 HTTP 请求）、把结果端回去 | **不做饭**，只负责收单和端菜 |
| **厨师** | `Service` | 真正干活：算钱、算库存、写数据库 | **不见客人**，只跟服务员对接 |
| **仓库管理员** | `Mapper` | 从数据库里取东西、放东西 | 只会按编号找货，不懂业务 |
| **货品规格说明** | `Entity` | 描述一件货长什么样（商品有名字、价格、库存） | 一张表对应一个 Entity |
| **客人手写的点菜单** | `DTO` | 前后端之间传递的数据形状 | 只管格式，不管味道 |

### 一个完整的点菜过程

顾客说："给我来一份采购单，买 100 瓶可乐。"

```
HTTP 请求（点菜）
   ↓
BillController.create(...)      ← 服务员接到单，检查格式对不对
   ↓  把单子翻译成厨房能懂的 BillDto
BillService.createDraft(...)    ← 厨师按菜谱做
   ↓  需要查商品是否存在
ProductMapper.selectById(...)   ← 管理员去仓库拿货
   ↓
返回结果一路往回传 → 变成 JSON 还给前端（端菜）
```

**为什么不把代码全写在一个文件里？**
因为这样改的时候不会互相搞乱。改菜单界面不用动厨师，换数据库不用重写业务逻辑。

> **这是这个项目最重要的约定。** 你后面看任何一个功能，都可以先问自己：
> "它的 Controller 是哪个？Service 是哪个？动了哪张表？"

## 三、注解（那些 `@` 开头的东西）

### 注解是什么？

**便利贴。** 你在代码上贴一张便利贴，Spring（管家）看到便利贴就知道该怎么对待这段代码。

| 便利贴 | 贴在谁身上 | 意思是 |
|---|---|---|
| `@RestController` | 类 | "这是个服务员，会接待网络请求" |
| `@RequestMapping("/api/bills")` | 类 | "这个服务员管 `/api/bills` 开头的地址" |
| `@GetMapping` | 方法 | "有人用 GET 方式访问这个地址，就执行这个方法"（查数据用） |
| `@PostMapping` | 方法 | "有人 POST 过来数据，就执行这个"（提交数据用） |
| `@PutMapping` / `@DeleteMapping` | 方法 | 改 / 删 |
| `@RequestBody` | 参数 | "请求里的 JSON，帮我转成对象塞进这个参数" |
| `@PathVariable` | 参数 | "网址里的那段，比如 `/bills/123` 的 123" |
| `@RequestParam` | 参数 | "网址问号后面的参数，比如 `?status=DRAFT`" |
| `@Service` | 类 | "这是个厨师，管家你帮我创建好放着，谁要用就给谁" |
| `@Component` | 类 | "这也是管家要管理的零件" |
| `@RequiredArgsConstructor` | 类 | Lombok 的：自动生成一个构造方法（讲见下） |
| `@Slf4j` | 类 | 送你一个 `log` 变量，可以打日志 |
| `@Transactional` | 方法 | **"这个方法要么全做完，要么全不做"**（见下） |
| `@Configuration` | 类 | "这是配置中心，我在这里注册零件" |
| `@PostConstruct` | 方法 | "管家创建好这个对象之后，立刻执行我一次" |
| `@Scheduled(cron="...")` | 方法 | "每天这个点自动执行我一次" |

### 关于 `@Transactional`（最重要的一个）

想象转账：从 A 扣 100，给 B 加 100。
**如果扣了 A 的钱，正要给 B 加的时候突然断电了怎么办？**

`@Transactional` 就是来解决这个问题的：

```java
@Transactional
public Bill post(Long billId) {
    // 写库存流水
    // 更新商品成本
    // 生成会计凭证
    // ↑ 这三步中任何一步出错，前面做过的全部自动撤销，就好像从没发生过
}
```

这个项目的核心业务方法**几乎都贴了这个便利贴**。你写新方法时如果会改多处数据，请一定加上它。

## 四、依赖注入："你要的工具，管家给你送来"

看这行代码：

```java
@Service
@RequiredArgsConstructor
public class BillService {
    private final BillMapper billMapper;
    private final BillItemMapper itemMapper;
    private final VoucherService voucherService;
    // ...
}
```

你有没有疑惑：**这些字段明明没赋值，怎么就能用？**

答案：

1. `private final` + `@RequiredArgsConstructor`（Lombok 提供的）
   → Lombok 在编译时**偷偷帮你生成了一个构造方法**，参数是所有 `final` 字段
2. Spring 管家看到这个类需要一个 `BillMapper`
   → 它刚好手里有（因为 `@Component`/`@Service` 的类都被管家建好了）
   → 就自动塞进去

这叫**依赖注入**。好处：`BillService` 不用自己 `new` 任何东西，测试的时候可以塞假的实现进去。

> **你想加一个依赖怎么办？** 就在字段列表里加一行 `private final XxxMapper xxxMapper;`
> 语法对了，管家自动给你。这就是这个项目里最常写的一行代码。

## 五、MyBatis-Plus：用中文句子查数据库

传统写法要写 SQL 字符串，拼错一个列名就崩，而且编译器不会提醒你。
这个项目用的是 **LambdaQueryWrapper**，长这样：

```java
List<BillItem> items = itemMapper.selectList(
    new LambdaQueryWrapper<BillItem>()
        .eq(BillItem::getBillId, billId)      // WHERE bill_id = billId
);
```

翻译成 SQL 就是：`SELECT * FROM bill_item WHERE bill_id = ?`

常用动词：

| 代码 | 对应 SQL | 意思 |
|---|---|---|
| `.eq(A::getX, v)` | `x = v` | 等于 |
| `.ne(...)` | `x <> v` | 不等于 |
| `.like(A::getName, "可乐")` | `name LIKE '%可乐%'` | 模糊匹配 |
| `.likeRight(A::getBillNo, "DJ20260912-")` | `bill_no LIKE 'DJ20260912-%'` | 前缀匹配 |
| `.orderByDesc(Bill::getId)` | `ORDER BY id DESC` | 倒序排 |
| `.last("limit 200")` | `LIMIT 200` | 直接拼 SQL 尾巴（兜底手段） |
| `.ge/.le/.gt/.lt` | `>= <= > <` | 比较 |

**为什么用 `BillItem::getBillId` 这种写法？**
因为写错列名的时候，编译器会直接报错（红色波浪线），而不是等运行到一半崩掉。这叫"编译期安全"。

## 六、HTTP / REST / JSON：前后端怎么说话

### HTTP 是什么

浏览器和服务器说话的规矩。每次对话包含四部分：

```
方式 + 地址            POST /api/bills
头信息                X-Auth-Token: abc123（我是谁）
                     Content-Type: application/json（我发的是 JSON）
正文（body）          {"type":"PURCHASE", "items":[...]}
服务器回答            200 OK + {"id":1,"billNo":"DJ...","total":300}
```

规矩约定（叫 REST）：

| 动作 | 用什么方式 | 例子 |
|---|---|---|
| 查数据 | GET | `GET /api/products` |
| 新增 | POST | `POST /api/bills` |
| 改 | PUT | `PUT /api/products/5` |
| 删 | DELETE | `DELETE /api/products/5` |

### JSON 是什么

数据在网线上传输时用的格式。人也能看懂：

```json
{
  "type": "PURCHASE",
  "warehouseId": 1,
  "discount": 95,
  "items": [ { "productId": 12, "quantity": 24, "price": 3.5 } ]
}
```

前端把它组装好发过来，Java 里的 **Jackson** 自动把它变成一个 `BillDto` 对象
（这就是 `@RequestBody BillDto dto` 干的事）。反过来，Java 返回对象时自动变回 JSON。

> **DTO = 数据传输对象**。它就是一份"格式说明书"，告诉两边：这次通话，可以带哪些字段。
> 看 `backend/src/main/java/com/local/erp/dto/BillDto.java`，只有 30 行，一目了然。

## 七、Token：进门的电子手环

这个项目**不用 Cookie/Session**，用的是"电子手环"（token）：

1. 你输账号密码登录 → 服务器核对正确 → 生成一个随机字符串 `abc123...` 存起来，发给你
2. 你之后每个请求都在**请求头**里带上 `X-Auth-Token: abc123...`
3. 服务器每次查一下这个字符串认不认识 → 认识就放行

```java
// AuthInterceptor.preHandle
SessionUser user = tokenStore.get(request.getHeader("X-Auth-Token"));
if (user == null) { response.setStatus(401); return false; }   // 不认识，401 请重新登录
```

前端在 `api.js` 里用 axios 拦截器统一加手环，所以**页面代码里完全不用关心这件事**：

```js
axios.interceptors.request.use(cfg => {
  const t = localStorage.getItem('erp_token')
  if (t) cfg.headers['X-Auth-Token'] = t
  return cfg
})
```

⚠️ **重要**：这个手环存在服务器的**内存**里（一个 Map）。所以：

- 服务器一重启，内存清空 → 所有人都得重新登录
- 存的地方是 `TokenStore.java`，一个 `ConcurrentHashMap`

## 八、ThreadLocal：每个服务员自己的小本子

服务器同时处理很多请求（多线程）。怎么保证 A 用户的请求不会读到 B 用户的身份？

答案是 `ThreadLocal` —— 一个"只有当前线程看得见"的盒子。

```java
private static final ThreadLocal<SessionUser> CURRENT = new ThreadLocal<>();
...
CURRENT.set(user);                          // 请求进来：把登录者记在小本子上
// ...业务代码里随时 AuthInterceptor.currentUser() 取...
public void afterCompletion(...) { CURRENT.remove(); }   // 请求结束：擦掉，防止串台
```

所以你在任何业务代码里看到 `AuthInterceptor.currentUser()`，意思就是"拿当前登录的人是谁"。

## 九、出错是怎么处理的

后端抛异常的地方到处都是：

```java
throw new IllegalArgumentException("库存不足：" + p.getName() + " 仅剩 " + cur);
```

但前端显示的错误是这样的：`{"error": "库存不足：可口可乐 仅剩 3"}`

中间是 `GlobalExceptionHandler` 做的翻译：

| 抛出的异常 | 变成 HTTP 状态 | 前端看到 |
|---|---|---|
| `IllegalArgumentException` | 400 | `{"error": "..."}` 直接显示给用户 |
| `SecurityException` | 403 | 权限不足 |
| 其它异常 | 500 | `{"error":"服务器内部错误：..."}`，详细堆栈只进日志 |

> **所以：业务上"这里不允许"，就 `throw new IllegalArgumentException("人话提示")`。**
> 这个提示会一字不差地显示在用户屏幕上。这是这个项目统一的错误提示方式。

## 十、前端名词傻瓜表

前端一个典型的 `.vue` 文件分三块：

```vue
<script setup>          ← JavaScript 逻辑放这里
  const list = ref([])              // ref = 一个"会自动触发界面更新"的变量
  const total = computed(() => ...) // computed = 会自动重算的值（依赖变了它跟着变）
  async function load(){ list.value = await api.products() }  // async = 耗时操作
  onMounted(load)                   // onMounted = 页面刚打开时执行一次
</script>

<template>              ← HTML 界面放这里
  <el-table :data="list">          ← el- 开头的是 Element Plus 组件库的现成零件
    <el-button @click="load">刷新</el-button>   ← @click 绑定上面的函数
  </el-table>
</template>

<style> ... </style>    ← CSS 样式放这里
```

| 名词 | 人话 |
|---|---|
| `ref([])` | 一个装着数据的盒子。**改的时候要写 `.value`**（脚本里），模板里不用 |
| `computed(...)` | 会自己重新计算的值。比如总价 = 数量×单价，数量变了它自动更新 |
| `async / await` | "这件事要花时间（比如请求网络），我等它"。await 后面可以当同步用 |
| `onMounted` | 页面第一次显示时调用一次，一般用来拉第一屏数据 |
| `v-if` / `v-for` | 条件显示 / 循环渲染列表 |
| `axios` | 发 HTTP 请求的工具，全部封在 `src/api.js` 里了 |
| Vite proxy | 开发时 `/api` 自动转发到 `localhost:8080`，假装同源，避开跨域 |
| Element Plus | 现成的后台 UI 组件库，`el-table`、`el-form`、`el-dialog` 全是它 |

## 十二、速查表：看到这个就当它是

| 你看到的 | 就当它是 |
|---|---|
| `import xxx` | 我要用别人家的东西 |
| `@Xxx` 在类/方法上面 | 一张便利贴，告诉框架怎么对待它 |
| `private final A a;` 没赋值 | 管家会自动塞进来，直接用就好 |
| `Map.of("a", b, "c", d)` | 造一个小字典：a→b，c→d |
| `List.of(...)` | 造一个只读列表 |
| `record Foo(a, b) {}` | 一个只有字段、没有逻辑的简写类（像结构体） |
| `Map<String, Object>` | 一个"什么都装"的字典，动态拼 JSON 时常用 |
| `LinkedHashMap` | 字典，但**保持你放入的顺序**（返回给前端时要字段有序就用它） |
| `Optional.ofNullable(x).orElse(y)` | x 不为空用 x，为空用 y |
| `x == null ? a : b` | 三元表达式，同上 |
| `.stream().map(...).toList()` | 把列表里每个元素加工一下，得到新列表 |
| `.stream().filter(...)` | 筛掉不符合条件的 |
| `Collectors.toMap(...)` | 把列表变成字典 |
| `String.format("%04d", 7)` | 补零成 `0007` |
| `Math.round(v*100)/100.0` | 保留两位小数 |
| 三层引号 `""" ... """` | Java 15+ 的多行字符串，这个项目用它写大段提示词 |
