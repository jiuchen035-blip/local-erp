# 07 · 前端、小程序与打包：界面和交付

---

## 一、前端最特别的一点：**它没有用路由**

绝大多数 Vue 项目都会装 `vue-router`，页面切换靠网址变化。
这个项目**没有**（`package.json` 里确实没这个依赖）。

### 那页面怎么切换的？

`App.vue` 里有一张"映射表"：

```js
const view = ref('dashboard')       // 当前显示哪个页面，就是一个字符串变量
const views = {
  dashboard: { comp: Dashboard, title: '经营看板' },
  products:  { comp: Products,  title: '商品管理' },
  orders:    { comp: Orders,    title: '进货 / 销售' },
  ...
}
```

模板里一行搞定：

```html
<el-menu :default-active="view" @select="k => view = k">...</el-menu>
<component :is="views[view].comp" />
```

`<component :is="...">` 是 Vue 的"动态组件"：给它什么组件，它就渲染什么。

### 为什么这么干？

| | 用 vue-router | 现在这样 |
|---|---|---|
| 网址能分享/刷新 | ✅ | ❌ 刷新就回看板 |
| 需要学的概念 | 路由、守卫、嵌套路由 | 一个变量 |
| 代码量 | 多几十行 | 一眼看完 |
| 适用场景 | 多页面 SaaS | **单 exe 桌面软件** |

**这是个合理的取舍**：软件是双击打开的，老板不需要收藏网址，也不需要分享链接。

### 代价（你要知道）

- 浏览器按 F5 刷新 → 回到"经营看板"（因为 `view` 初始值就是这样）
- 切换页面时组件**重新创建**（没有被 keep-alive 缓存），每次都会重新请求数据
- 401 的处理比较粗暴：`location.reload()` —— 整个页面重载

> 如果你的第一个任务是"加个页面"，这是最简单的。如果第二个任务是"加路由"，那你得先引入 vue-router。

## 二、一个页面是怎么组织的（以进货/销售页为例）

打开 `frontend/src/views/Orders.vue`，结构是：

```
<script setup>
  ├─ import          引入 api、组件、工具函数
  ├─ ref 定义一堆响应式变量
  │    products / partners / warehouses / bills   ← 从后端拉来的列表
  │    form / lines / pick                        ← 当前正在编辑的东西
  ├─ computed 定义自动计算的值
  │    grossTotal  = 各行 数量×单价 相加
  │    total       = grossTotal × 折扣 ÷ 100
  │    partnerOptions = 按单据类型过滤出供货商或客户
  ├─ function 定义动作
  │    onTypeChange()   换单据类型时清空明细
  │    addItem()        加一行
  │    submit()         调 api.createBill / api.postBill
  └─ onMounted(load)    页面打开先拉数据
</script>

<template>   ← 界面：el-card 包着 el-form、el-table、el-dialog
```

### 最有代表性的几个 computed

```js
const grossTotal = computed(() => lines.value.reduce((s, l) => s + l.quantity * l.price, 0))
const discount   = computed(() => form.value.discount == null ? 100 : form.value.discount)
const total      = computed(() => grossTotal.value * discount.value / 100)
const isOut      = computed(() => ['SALE','PURCHASE_RETURN','LOSS'].includes(form.value.type))
```

**为什么用 computed 而不是函数？** 因为 computed 有缓存，而且依赖一变界面自动刷新。
你在表格里改了某一行的数量，最下面的"合计"立刻跟着变，不用写任何额外代码。

### 数据怎么和后端对齐的

前端 push 一行时，组装的就是 `BillDto` 的形状（对照 `dto/BillDto.java`）：

```js
await api.createBill({
  type: form.value.type,
  warehouseId: form.value.warehouseId,
  partnerId: form.value.partnerId,
  paid: form.value.paid,
  discount: form.value.discount,
  remark: form.value.remark,
  autoPost: true,                    // true = 保存并过账
  items: lines.value.map(l => ({ productId: l.productId, quantity: l.quantity, price: l.price }))
})
```

**这就是前后端的契约。** 想加一个字段，两边一起加，就通了。

## 三、api.js：所有网络请求集中在这里

```js
axios.interceptors.request.use(cfg => {
  const t = localStorage.getItem('erp_token')
  if (t) cfg.headers['X-Auth-Token'] = t      // 自动带手环
  return cfg
})
axios.interceptors.response.use(
  r => r,
  err => {
    if (err.response?.status === 401) {
      localStorage.removeItem('erp_token')
      if (!location.hash.includes('login')) location.reload()   // 401 → 清手环 → 重载
    }
    return Promise.reject(err)
  }
)
```

下面就是一整个字典：

```js
export const api = {
  login: (u, p) => post('/api/auth/login', { username: u, password: p }),
  products: (keyword, category) => get('/api/products?...'),
  createBill: (dto) => post('/api/bills', dto),
  postBill: (id) => post(`/api/bills/${id}/post`),
  aiChat: (message) => post('/api/ai/chat', { message }),
  // ...一共 80 多个
}
```

> **想加一个接口调用，就在这个字典里加一行。** 页面里永远不直接写 axios。
> 这是很好的习惯：一旦后端改了地址，你只需要改这一行。

## 四、两个很有意思的实现细节

### 1. 打印：靠 CSS 而不是插件

做法很巧：页面上放一个**平时隐藏**的 `<div id="print-area">`，里面排版好单据的样子。

```css
#print-area { display: none; }
@media print {
  body > *:not(#print-area) { display: none !important; }   /* 打印时把整个页面藏起来 */
  #print-area { display: block !important; }                /* 只露出单据 */
  .receipt table { width: 100%; border-collapse: collapse; }
}
```

调用 `window.print()` 时，打印机就只看到那张单据了。

还做了纸张适配（`utils/print.js` 里的 `PaperSelect` 组件）：

```css
.paper-A4 .receipt   { max-width: 98%; }
.paper-ticket80 .receipt { max-width: 300px; font-size: 12px; }   /* 80mm 小票 */
```

> **免安装、免插件、跨平台。** 老板点"打印"出来的就是一张正规的单据。

### 2. 导出 Excel：纯前端完成

用 `xlsx`（SheetJS）在浏览器里生成文件，后端完全不参与：

```js
exportExcel(['商品','SKU','库存','售价'], rows, '商品列表.xlsx')
```

好处：**不占服务器资源，也不用等网络。**

## 五、表格为什么有时卡（以及怎么表现的）

商品列表上千行时，`el-table` 全量渲染会卡。项目的做法是**客户端分页**：

```js
const page = ref(1)
const pagedList = computed(() => all.value.slice((page.value - 1) * 100, page.value * 100))
```

只渲染当前这 100 行。**但导出和统计仍然用全量数据**，所以老板导出的 Excel 是完整的。
这个细节很重要：**显示优化了，但业务结果不能打折。**

## 六、动手：加一个新页面（四步）

1. **写页面**：在 `src/views/` 下新建 `MyPage.vue`
2. **注册到 App.vue**：

```js
import MyPage from './views/MyPage.vue'
const views = {
  ...
  mypage: { comp: MyPage, title: '我的新页面' },
}
```

3. **加菜单项**（在 `<el-menu>` 里）：

```html
<el-menu-item index="mypage"><el-icon><Star /></el-icon>我的新页面</el-menu-item>
```

4. **如果只要管理员看到**：

```html
<el-menu-item v-if="role === 'ADMIN'" index="mypage">...</el-menu-item>
```

> ⚠️ **前端隐藏不等于真的安全。** 真正的权限判断在后端 `AccessRules`。
> 如果你的页面调的是管理员接口，后端会拦住普通操作员；反之则请同步改后端规则。

## 七、微信小程序：一行后端代码都没改

### 它是怎么复用的

小程序的 `utils/api.js` 和网页版是同一套思路：

```js
function request(method, path, data) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + path,          // 后端地址（cpolar 隧道）
      method, data, timeout: 60000,
      header: { 'X-Auth-Token': wx.getStorageSync('token') || '',
                'Content-Type': 'application/json' },
      success(res) {
        if (res.statusCode === 401) { 清 token; 跳登录页; reject }
        if (res.statusCode >= 400) reject(new Error(res.data.error || res.data.message))
        resolve(res.data)
      },
      fail(e) { reject(new Error('网络连接失败，请检查隧道是否开启')) }
    })
  })
}
```

**因为后端本来就是纯 REST + 自定义 token 头，小程序理论上可以直接接入。**

### 唯一的改动点：地址

```js
// miniprogram/config.js
const BASE_URL = 'https://xxxx.r12.cpolar.top'     // cpolar 隧道地址
```

> 免费版 cpolar 的地址每次重启都会变，改这里就行。
> 正式上线需要已备案的域名（这是微信的硬性要求）。

### 限制要知道

- 后端电脑必须开机 + 隧道在线，小程序才能访问
- 后端重启 → token 失效 → 重新登录
- 开发时要在开发者工具里勾选"不校验合法域名"

## 八、打包：怎么变成别人能用的 exe

### 整体流水线

```
① npm run build                     → frontend/dist（一堆静态文件）
② mvn package                       → 先把 dist 拷进 jar 的 static/，再打成 jar
③ jpackage                          → 生成自带精简 JRE 的 app-image + exe
④ 打 zip                            → 绿色免安装版
⑤ ISCC（Inno Setup）                → 单文件安装包
```

第 ② 步的"自动拷贝"发生在 `pom.xml` 里：

```xml
<plugin>  <!-- maven-antrun-plugin -->
  <execution>
    <phase>generate-resources</phase>
    <target>
      <copy todir="${project.build.outputDirectory}/static">
        <fileset dir="../frontend/dist" erroronmissingdir="false"/>
      </copy>
    </target>
  </execution>
</plugin>
```

`erroronmissingdir="false"` 保证：**没构建前端也能打包后端**（只是没有界面）。

### jpackage 打包出的目录

```
账管卫士/
├─ 账管卫士.exe          ← 启动器（不是真正的程序）
├─ 账管卫士-控制台启动.bat  ← 排错神器（绕过启动器，能看见报错）
├─ app/
│   ├─ 账管卫士.cfg      ← ★ 有这个文件 = "我是打包运行"，AppHome 靠它定位数据目录
│   ├─ local-erp-0.6.0.jar
│   └─ data/             ← 数据在这！删掉整个文件夹 = 卸载干净
└─ runtime/              ← 自带的精简 Java 运行时
```

> **一定要整个文件夹解压出来再双击 exe。**
> 在压缩软件窗口里直接双击 exe，Windows 只会把 exe 单独解到临时目录，
> 它找不到旁边的 `runtime/`，就报"Failed to launch JVM"。
> 这是新手最容易踩的坑，占所有安装问题的 90%。

### 为什么逻辑全写在 PowerShell 里？

因为 bat 在中文路径 + 括号路径下会命令错乱（cmd 的代码页问题）。
所以：**bat 只做一行 ASCII 的"启动器"，真正的逻辑全在 `.ps1` 里。**

PowerShell 原生支持 Unicode，不会有这种问题。
