# 09 · 排错实战：两个真实故障，从现象到修复

> 这一章不讲课，只做一件事：**拿你遇到的两个真实问题，把"怎么找到、怎么确认、怎么改"完整走一遍。**
> 你以后遇到任何"点了没反应""数字不对"，都可以照这个流程走。

---

## 零、先记这个万能三步法

**任何"点了没反应 / 结果不对"，都按这三步查，不要瞎猜：**

```
第 1 步  浏览器按 F12 → Console（红字报错？） + Network（请求发出去了吗？后端回了啥？）
第 2 步  看后端日志（data/logs/local-erp.log，或者运行 jar 的那个黑窗口）
第 3 步  拿着错误信息回到代码里搜，定位到具体文件行号
```

**90% 的问题在第 1 步就能定性。** 分不清"前端的锅还是后端的锅"时，看 Network：

| Network 里看到什么 | 说明 | 去哪查 |
|---|---|---|
| **根本没有这条请求** | 前端根本没发出去 → **前端的锅** | 看那个按钮的 `@click` 绑到哪了 |
| 有请求，状态 **200**，但页面没变化 | 后端正常返回了，前端没处理 | 看前端拿到数据后的代码 |
| 状态 **400**，返回 `{"error":"XXX"}` | 后端**明确拒绝**了，原因就写在 error 里 | 看后端那个接口 |
| 状态 **401** | 没登录/登录过期 | 重新登录 |
| 状态 **403** | 权限不够（操作员点了管理员功能） | `AccessRules` |
| 状态 **500** | 后端崩了 | **必须看后端日志** |

## 故障一：点"新增操作员"没反应

> 说明：界面上这个按钮叫"新增操作员"，角色下拉里选"管理员"就是新增管理员，是同一个功能。

### 第 1 步：先判断有没有发出请求

按 F12 → Network → 点那个"新增操作员"按钮。

**结果：Network 里什么都没有。** 说明前端压根没发请求 —— 问题**一定在前端**。

### 第 2 步：顺着按钮找代码

界面上有"新增操作员"这几个字，全局搜一下它在哪（用编辑器搜索，搜中文"新增操作员"）。

找到：`frontend/src/components/UserManage.vue` 第 40 行

```js
<el-button type="primary" @click="add">新增操作员</el-button>
```

`@click="add"`，那就看 `add` 函数（第 11 行）：

```js
function add() { form.value = { username:'', password:'', role:'OPERATOR' }; dialog.value = true }
```

它做了两件事：清空表单、把 `dialog` 设为 `true`。

**`dialog = true` 的意思是"把弹窗显示出来"。那弹窗在哪？**

### 第 3 步：找弹窗，发现它不见了

继续往下翻这个文件的 `<template>` 部分，你会发现：

```
第 39 行  <template>
第 40 行    <el-button>新增操作员</el-button>
第 41 行    <el-table> ... 用户列表 ... </el-table>
第 65 行  </template>
```

**整个模板里只有一个按钮和一张表格，没有任何 `<el-dialog>`！**

这就是"点了没反应"的原因：

> 按钮其实**生效了**（`dialog` 变量确实变成 `true`），
> 但页面上**根本没有弹窗组件**可以显示，也没有任何输入框让你填用户名和密码。
> 所以你看到的就是"什么都没发生"。

再验证一下：`form` 这个变量在第 8 行定义了，但**全文没有任何地方用到它**（没有 `v-model="form.username"`）。
一个定义了却没人用的变量 —— 典型的"代码被删掉了一半"。

**结论：`<el-dialog>` 那一段在某次改动中丢了。后端完全没参与，看后端日志也没用。**

### 第 4 步：怎么改

在 `UserManage.vue` 的 `</el-table>` 后面（也就是 `</template>` 之前），加上这段：

```html
<el-dialog v-model="dialog" title="新增操作员" width="420px">
  <el-form :model="form" label-width="80px">
    <el-form-item label="用户名" required>
      <el-input v-model="form.username" autocomplete="off" />
    </el-form-item>
    <el-form-item label="密码" required>
      <el-input v-model="form.password" type="password" show-password
                autocomplete="off" placeholder="至少 6 位" />
    </el-form-item>
    <el-form-item label="角色">
      <el-select v-model="form.role" style="width:100%">
        <el-option label="操作员" value="OPERATOR" />
        <el-option label="管理员" value="ADMIN" />
      </el-select>
    </el-form-item>
  </el-form>
  <template #footer>
    <el-button @click="dialog = false">取消</el-button>
    <el-button type="primary" @click="save">确定</el-button>
  </template>
</el-dialog>
```

**为什么这么写就够了？** 因为 `save()` 函数（第 12 行）本来就是好的：

```js
async function save() {
  try {
    const r = await api.createUser(form.value)   // 把表单整份发给后端
    ElMessage.success(r.message)
    dialog.value = false
    load()                                       // 刷新列表
  } catch (e) { ElMessage.error(e.response?.data?.error || '创建失败') }
}
```

后端 `UserController.create`（第 37 行）也是好的，它会校验"用户名不能为空、密码至少6位、用户名不能重复"，
不合法就返回 `{"error":"用户名不能为空，密码至少6位"}`，前端 catch 到就弹红字提示。

### 第 5 步：验证

1. `cd frontend && npm run build`（或者直接 `npm run dev` 看效果）
2. 登录管理员账号 → 系统设置 → 点"新增操作员" → **应该弹出输入框了**
3. 填 `test / 123456 / 操作员` → 确定 → 应该提示"已创建 test"，列表里多一行
4. 故意填 `test / 123`（密码才 3 位）→ 应该**弹红字**"用户名不能为空，密码至少6位"
   → 如果看到了这句红字，说明**后端也通了**，整条链路都是好的

## 故障二：二级分类显示"0 个商品"，但点进去明明有货

### 现象回顾

商品管理页是"分类磁贴"式的：

```
[饮料  12个]  [零食  8个]      ← 一级分类，数字是对的
        ↓ 点"饮料"
[汽水  0个]  [果汁  0个]        ← 二级分类，全是 0，但点"汽水"进去能看到商品
```

数字是 0，点进去却有货 —— **说明"统计数字"和"实际筛出来的列表"用了两套逻辑，统计那套算错了。**

### 第 1 步：这肯定是前端算的

数据没有经过后端（后端只给了商品列表和分类字典），所以**不用看后端日志**。
直接在前端搜"个商品"这三个字（磁贴上显示的文案）。

找到：`frontend/src/views/Products.vue` 第 304 行

```html
<div style="font-size:12px;color:#909399;margin-top:4px">{{ t.count }} 个商品</div>
```

那 `t` 来自 `tiles`，`tiles` 在第 54 行。

### 第 2 步：读这段统计代码

```js
// 当前层级应显示的子分类磁贴（含商品数）
const tiles = computed(() => {
  const count = fn => all.value.filter(p => inScope(p) && fn(p)).length   // ← ①
  if (!sel.value.l1)
    return catDict.value.categories.map(c => ({ name: c, count: all.value.filter(p => p.category === c).length }))  // ← ②
  if (!sel.value.l2) return l2Options.value.map(c => ({ name: c, count: count(p => (p.subCategory || '') === c) }))  // ← ③
  if (!sel.value.l3) return l3Options.value.map(c => ({ name: c, count: count(p => (p.sub2Category || '') === c) })) // ← ④
  return []
})
```

注意 **② 和 ③ 的写法不一样**：

- **② 一级分类**：直接 `all.value.filter(p => p.category === c)` —— 数"分类等于 c 的所有商品"。**没用 inScope，所以是对的。**
- **③ 二级分类**：用的是 `count(...)`，而 `count` 里面**多了一个 `inScope(p)`**。

那 `inScope` 是什么？看第 26 行：

```js
function inScope(p) {
  const s = sel.value
  if (!s.l1) return !p.category                  // 根层级：只显示"未分类"的
  if (p.category !== s.l1) return false
  if (!s.l2) return !(p.subCategory || '')       // ★ 一级层：只显示"没有二级分类"的直属商品
  if ((p.subCategory || '') !== s.l2) return false
  if (!s.l3) return !(p.sub2Category || '')      // ★ 二级层：只显示"没有三级分类"的
  return (p.sub2Category || '') === s.l3
}
```

### 第 3 步：找出矛盾（关键的一步）

现在把 ③ 的逻辑摊开。此时你已经点进了一级分类（比如"饮料"），`sel.l1 = "饮料"`、`sel.l2 = ''`。

`count(p => (p.subCategory || '') === "汽水")` 的实际条件是：

```
条件 A（来自 inScope）：  这个商品【没有】二级分类         ← 因为 sel.l2 是空的
条件 B（来自 fn）：       这个商品的二级分类【等于】"汽水"  ← 我们要数的目标

A 和 B 互相矛盾！一个商品不可能"没有二级分类"又"二级分类等于汽水"
```

**所以结果永远是 0。** ④ 三级分类同理，也是 0。

> `inScope` 本身没有错 —— 它是给**右边商品列表**用的（列表确实只该显示"直属商品"，
> 子分类的商品要点磁贴下钻才看）。**错的是：统计子分类数量时，不该用它。**

### 第 4 步：佐证

同一个文件里还有一处也在数分类数量（第 149-159 行，"分类管理"弹窗）：

```js
if (p.category && p.subCategory) {
  const k2 = p.category
  counts2[k2 + '/' + p.subCategory] = (counts2[k2 + '/' + p.subCategory] || 0) + 1
}
```

这里**没有** `inScope`，用的是"分类+二级分类都对上就 +1"，所以**分类管理弹窗里的数字是对的**。

> 如果你发现"分类管理里的数字是对的，但磁贴上是 0"，就 100% 确认了上面这个判断。

### 第 5 步：怎么改

把 `tiles` 整个换成下面这段（**把 `inScope` 从统计里拿掉**，改成按"属于这个分类"来数）：

```js
const tiles = computed(() => {
  const s = sel.value
  // 统计某个子分类下的商品数：不看"直属不直属"，只看"是否属于这个分类"
  const matchCount = (level, name) => all.value.filter(p => {
    if (level === 1) return p.category === name
    if (level === 2) return p.category === s.l1 && (p.subCategory || '') === name
    return p.category === s.l1 && (p.subCategory || '') === s.l2 && (p.sub2Category || '') === name
  }).length

  if (!s.l1) return catDict.value.categories.map(c => ({ name: c, count: matchCount(1, c) }))
  if (!s.l2) return l2Options.value.map(c => ({ name: c, count: matchCount(2, c) }))
  if (!s.l3) return l3Options.value.map(c => ({ name: c, count: matchCount(3, c) }))
  return []
})
```

**为什么这么改是对的？**

- 一级磁贴"饮料"显示 12 → 点进去，二级磁贴"汽水 5 / 果汁 4 / 直属商品 3" → 加起来正好 12 ✓
- 和"分类管理"弹窗里的数字也对得上了 ✓
- 点进"汽水"看到的商品列表，就是这个数字对应的那些货 ✓

### 第 6 步：验证

1. `npm run dev`，进商品管理
2. 点一级分类 → 二级磁贴应该都有数字了
3. **把当前层级所有二级磁贴的数字加起来，再加上列表里的直属商品数，应该正好等于上一级磁贴显示的数字**
4. 点进某个二级分类 → 里面显示的商品数量，应该和磁贴上的数字一致

## 三、日志在哪、怎么看、怎么读懂

### 日志的两个去处

| 运行方式 | 日志去哪 |
|---|---|
| 双击打包的 exe | **文件**：`程序目录\data\logs\local-erp.log`（没有黑窗口，只能看文件） |
| `java -jar xxx.jar` | **黑窗口**（控制台）+ 同时写文件 |
| 用包里的 `账管卫士-控制台启动.bat` | **黑窗口**（这个 bat 就是专门为了看报错而存在的） |

文件位置（开发态）：`backend\data\logs\local-erp.log`
超过 10MB 自动切一个新文件，最多留 30 个（`local-erp.log`、`local-erp.1.log`……）。

> **开发调试建议：永远用 `java -jar` 在命令行里跑，不要双击 exe。**
> 报错直接刷在眼前，比翻文件快十倍。

### ⚠️ 一个很容易困惑的点：SQL 不在日志里

`application.yml` 里开了 `log-impl: StdOutImpl`，意思是"把每条 SQL 打到**标准输出**"。
**标准输出 = 黑窗口，不会写进 `local-erp.log` 文件。**

所以：

- 想看**系统日志**（启动信息、异常堆栈）→ 看文件或黑窗口，都行
- 想看 **SQL 语句** → **必须看黑窗口**（或者用 DB Browser 自己查）

### 怎么读懂一段日志

一条典型的 Spring Boot 日志长这样：

```
2026-09-12 20:31:07.482  INFO 12345 --- [nio-8080-exec-3] c.l.erp.service.BillService   : 单据过账完成
```

拆开看：

| 片段 | 是什么 |
|---|---|
| `2026-09-12 20:31:07.482` | 时间 |
| `INFO` | 级别：`ERROR` 最严重 > `WARN` > `INFO` > `DEBUG` |
| `12345` | 进程号（不用管） |
| `[nio-8080-exec-3]` | 哪个线程在处理（并发问题时有用） |
| `c.l.erp.service.BillService` | **哪个类打的**（缩写：`com.local.erp.service.BillService`） |
| 冒号后面 | 内容 |

### 出现异常时怎么看堆栈（最重要）

一段报错大概长这样，别被长度吓到：

```
2026-09-12 20:31:07.482 ERROR 12345 --- [nio-8080-exec-3] c.l.e.c.GlobalExceptionHandler : 接口异常

java.lang.IllegalArgumentException: 库存不足：可口可乐 仅剩 3，请改仓或减量
    at com.local.erp.service.BillService.post(BillService.java:259)          ← ① 看这里
    at com.local.erp.controller.BillController.post(BillController.java:106) ← ② 再看这里
    at java.base/java.lang.reflect.Method.invoke(Method.java:580)
    at ......（下面一大堆都是框架内部的，不用看）
```

**读法（就三招）：**

1. **只看第一行**：`异常类型: 人话描述`。
   这个项目里 99% 的业务错误都是 `IllegalArgumentException`，冒号后面是**作者写给老板看的中文**，
   比如"库存不足：可口可乐 仅剩 3"。**这一行基本就等于答案了。**
2. **从上往下找第一个 `com.local.erp` 开头的行**：那就是**出错的具体文件和行号**。
   上例是 `BillService.java:259` —— 直接去那个文件第 259 行看。
3. **下面那一长串 `org.springframework`、`java.base` 全是框架内部调用，跳过。**

### 常见异常对照表

| 你在日志里看到 | 意思 | 去哪查 |
|---|---|---|
| `IllegalArgumentException: xxx` | 业务校验没过，xxx 就是原因 | 全局搜那句中文 |
| `NullPointerException` | 某个对象是空的就拿来用了 | 看堆栈第一个 `com.local.erp` 行 |
| `no such column: xxx` | 老数据库没这个字段 | **忘了写 MigrationConfig 的 ALTER**（见 08 章） |
| `SQLITE_BUSY / database is locked` | 有两个程序同时开着一个库 | 关掉多余的程序 |
| `ClassNotFoundException` | 用 `mvn spring-boot:run` 在中文路径下启动 | 改用 `java -jar` |
| `Connection refused` | 要连的服务没起来（比如 Python 桥接 8317） | 去 AI 设置页看桥接状态 |
| `Failed to launch JVM` | exe 没解压 / 系统版本太低 | 用控制台启动.bat 看真报错 |

## 四、速查表：看到现象就知道去哪

| 现象 | 第一反应 | 具体位置 |
|---|---|---|
| 点了按钮**完全没反应** | 前端没发请求 | 搜按钮上的中文字 → 看 `@click` 绑的函数 |
| 点了**弹红字** | 后端拒绝了，error 里就是原因 | 全局搜那句红字 |
| 显示 **401** | 登录过期 | 重新登录 |
| 显示 **403 需要管理员权限** | 权限不够 | `config/AccessRules.java` |
| 显示 **500 服务器内部错误** | 后端崩了 | **看后端日志** |
| 数字不对/列表不对 | 前端算的，别看后端 | 搜页面上那个数字旁边的文字 |
| 数据没保存进去 | 先看 Network 有没有请求，再看后端日志 | 一般是字段没对上 |
| 界面卡 | 表格渲染太多行 | 加客户端分页（每页 100 行） |
| 打包后出问题，开发时没事 | 大概率是**文件路径** | `AppHome.java` |

## 五、最后：两个故障的根因一句话总结

| 故障 | 根因 | 修复 |
|---|---|---|
| 点"新增操作员"没反应 | `UserManage.vue` 的模板里**少了 `<el-dialog>` 弹窗**，`dialog=true` 无处可显示 | 补一段 `<el-dialog>`（上面第 4 步已给完整代码） |
| 二级分类数量显示 0 | `Products.vue` 的 `tiles` 统计时误用了 `inScope`，和"数某个子分类"的条件**互相矛盾** | 统计时去掉 `inScope`，改成按"是否属于该分类"来数（上面第 5 步已给代码） |

> 两个都是**纯前端问题**，后端日志里不会有半点线索 —— 这也是为什么"先看 F12 Network"能省你半小时。
