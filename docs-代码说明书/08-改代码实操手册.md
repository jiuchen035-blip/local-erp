## 需求 1 · 给商品加一个字段（例：颜色）

这是一个"要改动 4 个地方"的典型例子。跟着做一遍，你就掌握了套路。

### 第 1 步：数据库加列

打开 `backend/src/main/resources/schema.sql`，在 `product` 表里加：

```sql
color   TEXT DEFAULT '',      -- 颜色
```

### 第 2 步：让老库也能升级

打开 `config/MigrationConfig.java`，在那排 `try{ALTER}` 后面加一行：

```java
try { jdbc.execute("ALTER TABLE product ADD COLUMN color TEXT DEFAULT ''"); } catch (Exception ignored) {}
```

> **为什么两个地方都要写？**
> `schema.sql` 只管"全新的库"。已存在的老库不会因为改了 schema.sql 就自动加列，
> 所以必须有这条幂等迁移。**这是这个项目最重要的维护约定。**

### 第 3 步：Entity 加字段

```java
// entity/Product.java
private String color;
```

（Lombok 的 `@Data` 会自动生成 getter/setter，不用你写）

### 第 4 步：前端加显示/编辑

在 `views/Products.vue` 的表格里加一列，在表单里加一个输入框：

```html
<el-table-column prop="color" label="颜色" width="100" />
<el-form-item label="颜色"><el-input v-model="form.color" /></el-form-item>
```

### ✅ 验证

1. 重启后端（看一下有没有报 ALTER 错误）
2. 打开商品管理 → 新增 → 填上颜色 → 保存
3. 用 DB Browser 打开 `data/erp.db`，执行 `SELECT color FROM product LIMIT 5;`
4. 确认新字段确实写进去了

## 需求 2 · 加一个新功能（一个新的管理对象）

按这个顺序，一个都别漏：

| 顺序 | 做什么 | 文件 |
|---|---|---|
| 1 | 建表 | `resources/schema.sql` |
| 2 | 幂等迁移 | `config/MigrationConfig.java` |
| 3 | 实体类 | `entity/Xxx.java`（`@Data @TableName`） |
| 4 | Mapper | `mapper/XxxMapper.java`（空接口，继承 `BaseMapper<Xxx>`） |
| 5 | Service | `service/XxxService.java`（`@Service @RequiredArgsConstructor`，写业务、**加 `@Transactional`**） |
| 6 | Controller | `controller/XxxController.java`（`@RestController @RequestMapping`） |
| 7 | 前端接口 | `frontend/src/api.js` 里加方法 |
| 8 | 前端页面 | `views/` 下新建 `.vue`，并在 `App.vue` 注册 + 加菜单 |
| 9 | 权限（如果需要限制） | `config/AccessRules.java` 的 `ADMIN_PREFIXES` |

模板：

```java
@Service
@RequiredArgsConstructor
public class XxxService {
    private final XxxMapper xxxMapper;

    @Transactional
    public Xxx create(Xxx x) {
        // 1. 校验
        if (x.getName() == null || x.getName().isBlank())
            throw new IllegalArgumentException("名称不能为空");
        // 2. 落库
        xxxMapper.insert(x);
        return x;
    }
}
```

> **记住三条**：① 校验失败就 `throw new IllegalArgumentException("人话")`；
> ② 一次改多处数据就加 `@Transactional`；③ Controller 别写业务。

## 需求 4 · 给 AI 加一个工具

见 [06 章第十节](06-AI部分怎么跑.md#十动手给-ai-加一个新工具)，三步：写方法 → 注册定义 → 挂分发。

而且你完全不知道为什么。写法建议：**一句话说清"什么时候该用它，返回什么"。**

## 需求 5 · 改单据编号规则

位置：`service/BillService.java` 的 `nextBillNo()`。

现在是 `"DJ" + 当天日期 + "-" + 四位序号`（如 `DJ20260912-0001`）。

比如想改成带类型前缀（采购 PJ、销售 XS）：

```java
String prefix = switch (type) {
    case "PURCHASE" -> "PJ" + 日期 + "-";
    case "SALE"     -> "XS" + 日期 + "-";
    default         -> "DJ" + 日期 + "-";
};
```

注意 `nextBillNo()` 目前没有参数，需要把单据类型传进去（调用点在 `createDraft`）。

> ⚠️ **改这里之前先想清楚**：已经生成的老单号不会变，
> 界面上"今天最大号 +1"的逻辑依赖前缀匹配，前缀变了序号会**从头开始**，
> 而 `bill_no` 有 UNIQUE 约束 —— 不同前缀不冲突，所以是安全的；
> 但如果只是把 DJ 改成 PJ 而不按类型区分，可能撞号，请先导出老数据核对。

## 需求 7 · 改权限（谁能看什么）

**唯一应该改的地方**：`config/AccessRules.java`

```java
public static final List<String> ADMIN_PREFIXES =
        List.of("/api/users", "/api/system", "/api/finance", "/api/integrations");
public static final List<String> ADMIN_METHODS = List.of("DELETE");
```

- 想让某个模块只有管理员能用 → 把它的 URL 前缀加进来
- 想放开 → 删掉

**千万别只改前端的 `v-if`** —— 那只藏了菜单，接口还是能调（F12 打开控制台就能绕过）。

AI 那边会自动跟着变，因为它读的是同一个类。**这就是把规则抽出来的收益。**

PRESETS.put("myvendor", new Preset("我的厂家", "https://api.xxx.com/v1",

## 需求 9 · 加一个报表

1. 后端写一个 Controller 方法，用 `JdbcTemplate` 或 Mapper 查数据，返回聚合结果
2. 前端 `api.js` 加一个方法
3. 页面用 `el-table` + ECharts 展示，需要导出就调 `utils/export.js` 的 `exportExcel`

参考已有的 `ReportsController` + `views/Reports.vue`（它已经有月/季/年度、多 sheet 导出、
甚至"AI 美化经营报告"的完整实现，是很好的模板）。

> 聚合计算建议**尽量交给 SQL**（`GROUP BY`、`SUM`），
> 不要像现在某些地方那样把全表捞进 Java 内存再累加（见优化清单）。

## 需求 10 · 改税务 / 价格 / 折扣逻辑

| 想改什么 | 去哪 |
|---|---|
| 计税开关、默认税率 | `service/FinanceSettingsService.java`（界面上也能改） |
| 单个商品的税率 | `product.tax_rate`（为空就跟随全局） |
| 价税分离算法 | `service/VoucherService.splitNet()` |
| 采购成本是否按不含税入账 | `service/BillService.post()` 里 `netUnit` 那几行 |
| 整单折扣怎么分摊 | `BillService.post()` 开头 `effPrice = price * disc / 100` |
| 更多价格档位 | `product` 的 `sale_price / wholesale_price / member_price`，前端 `PRICE_MODES` |

> **改这块的铁律**：所有金额都必须源自同一个"实际成交单价"，
> 否则就会出现"单据上一个数、账上另一个数"的对不上账的情况。这是最容易出事故的一块。

## 排错清单

### 起不来

| 现象 | 原因 / 处理 |
|---|---|
| `Failed to launch JVM` | 没解压就点了 exe（exe 旁必须有 `app/` 和 `runtime/`）；用包里的**控制台启动.bat**看真实报错 |
| `mvn spring-boot:run` 报 ClassNotFound | 中文路径，改用 `java -jar` |
| 改了代码没效果 | bat 跑的是旧版本 jar（见开工前三件事） |
| 8080 被占 | 自动换 8081；想固定用 `--server.port=18080` |
| 想看详细错误 | `data/logs/local-erp.log` |

### 数据库

| 现象 | 原因 / 处理 |
|---|---|
| `no such column: xxx` | 老库没加到这个列。检查有没有写 `MigrationConfig` 那条 ALTER |
| `database is locked` | 有多个程序在写同一个 db 文件（比如同时开着开发态和打包态）。关掉多余的 |
| 数据乱了想重来 | 删掉 `data` 文件夹，重启 |
| 误操作想回退 | `backup/` 里有备份，用系统设置页的"恢复" |

### AI

| 现象 | 原因 / 处理 |
|---|---|
| 提示"未配置有效 API Key" | yml 里的占位文案会被判定无效；去界面里填真 Key |
| HTTP 422 `Field required` | Java 到 Python 桥接的 chunked 问题（本项目已修，如果你换回默认工厂会复发） |
| 网页版模型报"未登录" | AI 设置 → 点对应"登录"按钮，弹窗里登录一次 |
| 网页版响应慢 / 回答被截断 | 网页模式天生慢（每轮 40~90 秒是正常的），有速度要求请配 API Key |
| AI 不管你怎么问都答非所问 | 大概率是工具的 `description` 写得不够清楚，模型没选中它 |
| AI 执行了它不该做的事 | 检查 `needAdmin` 集合；AI 写操作只应产生草稿 |

### 前端

| 现象 | 原因 / 处理 |
|---|---|
| 表格上千行卡顿 | 用客户端分页（参考 `Products.vue` 的做法） |
| `el-select` 在弹层里点了就关 | 下拉默认 teleport 到 body，加 `:teleported="false"` |
| 上传文件没反应 | Element Plus 的回调参数是 `UploadFile`，真实文件在 `.raw` |
| 点"选择文件"没弹窗 | 别用 label 包按钮，用 `ref.click()` 直接调 |

## 最后：改代码的自查清单

改完别急着提交，走一遍：

- [ ] 涉及新字段：**schema.sql 和 MigrationConfig 都改了吗？**（最容易漏）
- [ ] 一次改多处数据：**加 `@Transactional` 了吗？**
- [ ] 业务校验：**用 `IllegalArgumentException` 抛出"人话"了吗？**（这样前端能直接显示）
- [ ] 列表接口：**加了 limit 上限吗？**
- [ ] 新接口需要限制：**改的是 `AccessRules` 而不是只改前端 `v-if` 吗？**
- [ ] AI 工具：**`description` 写清楚了吗？`required` 参数列全了吗？**
- [ ] 重启后端看一眼启动日志，有没有异常
- [ ] 实际点一遍：新增 → 编辑 → 删除 → 导出，全走一遍
- [ ] 如果是业务规则：**用一个手算的例子验证数字对不对**（像第 04 章那样）
- [ ] 改之前，`backend/data` 备份了吗？
