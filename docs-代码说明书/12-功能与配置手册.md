# Local-ERP 本地商家后台管理工具

类管家婆的本地进销存后台，单体架构 + 可拔插 AI 模块（RAG/Agent）。**当前版本 v0.4.0**（v0.2.0 财务记账+电商对接；v0.2.1 智能开单自动建档；v0.3.0 税务价税分离 + 现金流量表 + 记账凭证套打 + 年度结转；**v0.4.0 AI 模型三来源自动降级：云端 API → 本地 Ollama → 网页版模型（免API，妙想/DeepSeek 网页驱动）**）。
**对外分发名：账管卫士**（打包成免安装绿色版 zip 或单文件安装包发给任何人，
对方电脑无需装 Java/数据库，双击即用——详见 **[打包教程.md](打包教程.md)**，
一键打包脚本在 `package/` 目录）。

## 技术栈
- 后端：Spring Boot 3 + MyBatis-Plus + SQLite（本地零运维，数据在 `backend/data/erp.db`）
- 前端：Vue 3 + Element Plus + Vite
- AI：OpenAI 兼容协议统一封装，**API Key 云端测试 / 本地 Ollama 一键切换**

## 目录
```
backend/   Spring Boot 后端
  └─ src/main/java/com/local/erp
       ├─ controller   商品 / 库存单据接口
       ├─ service      库存=流水聚合（可追溯、可冲正）
       ├─ entity/mapper
       └─ ai           AiProperties + ModelClient + Text2SQL 助手
frontend/  Vue3 管理后台
```

## AI 模型配置（v0.4.0：三种来源 + 自动降级）

AI 设置（聊天页右上角 ⚙，管理员）选厂家即可，**即时生效无需重启**：

| 厂家选项 | 说明 | 需要什么 |
|---|---|---|
| **自动（推荐）** | 有效 API Key → 云端 API；否则 Ollama 在线 → 本地模型；都没有 → 自动用网页版模型 | 无 |
| DeepSeek / 智谱GLM / 通义千问 / Kimi / 硅基流动 / OpenAI | 云端 API（OpenAI 兼容协议） | 该厂家 API Key |
| Ollama本地 | 完全离线，零费用 | `ollama serve` + `ollama pull qwen2.5:7b` |
| **网页版模型（免API）** | 本机桥接服务（`webllm/`，127.0.0.1:8317）用 Playwright+Scrapling 驱动已登录的**东方财富妙想 / DeepSeek 网页**，对外暴露 OpenAI 兼容接口，四种 AI 模式全部可用（含 Agent 多轮工具调用，经 `<tool_call>` 文本协议转换） | 首次：Python 3.10+ 环境准备 + 网页登录一次 |
| 自定义 | 任何 OpenAI 兼容地址 | 地址 + Key |

**网页版模型首次使用三步**：
1. 环境准备（仅一次）：安装 Python 3.10+，在 `webllm/` 目录执行 `pip install -r requirements.txt`，再执行 `playwright install chromium`
2. AI 设置 → 厂家选「网页版模型（免API）」→ 点「DeepSeek 登录 / 妙想登录」→ 在弹出的浏览器里登录一次（登录态存 `webllm/profile/`，长期有效）
3. 保存。桥接未运行时后端会自动拉起；设置页可看运行状态、启动服务、打开登录窗口

限制：响应比 API 慢、同网站同时一个请求、网页改版可能需更新适配器选择器——定位为个人使用/兜底，非高并发方案。配置持久化在 `backend/data/ai-settings.json`，聊天页右上角标签实时显示当前实际来源（绿=API / 橙=网页版），悬停可看降级原因。知识库向量模型（`ai.embedding`）配置不变，网页模式下建议保持关闭（走关键词检索）。

## 知识库（RAG）
- 首次启动自动内置一份《系统操作指南》，AI 助手开箱即可回答“怎么用”类问题
- 检索双模式：
  - **关键词检索**（默认，零配置）：中文 2-gram + 整词加权匹配，够小规模使用
  - **语义检索**：配置 `ai.embedding` 后启用，余弦相似度暴力检索（向量化兼容智谱 embedding-3 / 硅基流动 bge-m3 / 本地 Ollama bge-m3），切换模型后点“重建向量索引”

## 核心设计
- **库存 = 流水聚合**：流水唯一入口是单据过账（BillService），调拨生成一出一入两条流水
- **移动加权平均成本**：每次采购过账重算 `product.avg_cost`（按折后价），销售流水记录结转成本 `cost_price`，毛利 = 销售额 - Σ结转成本（调拨/报损/退货不计入经营流水）
- **整单折扣**：过账时按行分摊，流水/应收/成本全部用折后价，保证单据金额与账一致
- **盘点**：差异自动生成盘盈（GAIN）/报损（LOSS）单，按加权成本计价，不污染毛利
- **冲正**：生成镜像反向单据并过账，原单保留；挂账单冲正时自动结清原单应收应付；库存不足时拒绝冲正
- **自动备份**：启动时 + 每晚23点 `VACUUM INTO` 热备到 `backend/backup/`，保留30份；恢复 = 停服后用备份覆盖 `data/erp.db`
- **鉴权**：BCrypt 密码 + 内存 token（重启需重新登录）；POST/PUT/DELETE 自动记录操作日志
- **Agent 安全边界**：AI 只能创建**草稿单**，过账必须人工确认
- **单 jar 部署**：`npm run build` 后再 `mvn package`，前端自动打进 jar 的 static/，一个 jar 一个端口跑全系统（http://localhost:8080）

## 六、常见问题（FAQ）

### 双击 exe 报「Failed to launch JVM」

按顺序排查（90% 是第 1 条）：

1. **绿色版没解压就直接双击了 exe**：必须先把整个文件夹解压出来再运行。判断标准：exe 旁边必须有 `app/` 和 `runtime/` 两个文件夹，没有 = 没解压（不能在压缩软件窗口里直接点 exe，Windows 只会把 exe 单独解到临时目录，导致找不到自带 JRE）
2. **系统不满足要求**：需要 Windows 10/11 64 位。Win 7 / Win 8 / 32 位系统无法运行内置的现代 Java 运行时
3. **杀毒软件隔离了 runtime 文件**：把程序文件夹加入白名单后重新解压/重装
4. **看真实报错**：双击同目录的 **`账管卫士-控制台启动.bat`** ——它绕过 exe 启动器、直接用自带 JRE 启动，任何错误都显示在黑窗口里；很多时候这个 bat 本身就能直接跑起来

### 网页版模型报「未登录」

登录态存在 `webllm/profile/<站点>/`。若过期或未登录：AI 设置 → 点对应「DeepSeek 登录 / 妙想登录」→ 在弹出的浏览器里完成登录，窗口检测到登录成功会自动关闭。妙想真实聊天页为 `https://ai.eastmoney.com/chat`。

### 其他

- **端口 8080 被占用**：`账管卫士.exe --server.port=18080`（快捷方式"目标"末尾追加参数）
- **重置全部数据**：停止程序后删除 `app/data`（开发态为 `backend/data`）
- **AI 网页模式响应慢**：正常现象（网页对话 + 单站点串行），Agent 多轮工具调用时更明显；对速度有要求请配置任意厂家 API Key（智谱 glm-4-flash 等有免费额度）
- **中文路径下开发不要用 `mvn spring-boot:run`**：JVM 参数文件编码错乱报 ClassNotFound，一律 `java -jar target\xxx.jar`
