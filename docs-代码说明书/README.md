## 二、整个项目一句话版本

> **这是一个给小商店老板用的"电子账本"，装在老板自己的电脑上，不要网、不要装数据库，
> 双击就能用；里面还塞了一个会帮你查账、帮你开单（但不敢替你拍板）的 AI 小助手。**

它由四块拼起来：

```
┌─ 老板看到的界面（网页 / 微信小程序）   —— 用 Vue 写的
├─ 后台大脑（一个 jar 包，端口 8080）     —— 用 Java + Spring Boot 写的
├─ 数据（一个文件 data/erp.db）           —— SQLite，18 张表
└─ AI 外挂（可选，端口 8317）             —— 用 Python 写的，专门用来"白嫖"网页版大模型
```

## 三、最重要的一件事：先看懂"三条铁律"

在看任何一行代码之前，请把这三条记住。这个项目 80% 的代码，都是在服务这三条规则。

### 铁律一：**库存不是抄在账上的，是"算"出来的**

你可能会以为：商品表里有个"当前库存 = 57"的字段。
**这个项目没有。** 它记录的是每一次进出货的流水：进 100、出 20、进 5……库存是把这些数字加起来得到的。

为什么这么干？因为这样**每一瓶货的去向都能追**。谁在什么时候拿走的，翻记录就行。
如果只是一个数字，库存莫名少了 3 瓶，你永远查不出来。

> 代价：算得慢一点。这是故意换来的。

### 铁律二：**单据分"草稿"和"已过账"，只有过账才真的动库存**

你在界面上开了一张销售单，库存**一动都没动**。它只是一条写在 `bill` 表里的草稿。
等你确认无误点了"过账"，系统才真的扣库存、算成本、生成会计凭证。

为什么？因为开单会填错。草稿随便改随便删，过账了就得用正规手续撤销（见铁律三）。

### 铁律三：**错单不删，用"冲正"**

开错了怎么办？**不允许删除。** 系统会生成一张一模一样、方向完全相反的单据并立刻过账。
比如你误卖了 10 瓶出去，冲正就是"再生成一张退货单把这 10 瓶退回来"。
**原来的那张错误单据永远保留**，老板查得出来当时发生了什么。

> 这叫"审计留痕"。正规财务软件都这么干。
