# 01 · 先建立画面：这个软件到底在管理什么

> 在记任何技术名词之前，我们先把它翻译成"小卖部老板的一天"。
> **代码里所有的类、表、字段，都是从这些现实动作里长出来的。**

---

## 一、小卖部老板的一天

### 早上：进货

老板从供货商老李那里进了 100 瓶可乐，3 块钱一瓶，一共 300 块，钱下个月再给（赊账）。

在这套软件里，这叫**一张"采购入库单"**（代码里的 `PURCHASE`）。它要记录：

| 现实中要记的 | 软件里存在哪 |
|---|---|
| 今天是几号、单号多少 | `bill.bill_no`、`bill.created_at` |
| 从谁那儿进的 | `bill.partner_id` → 指向"老李"这条供应商档案 |
| 货放到哪个仓库 | `bill.warehouse_id` |
| 进了什么、多少、什么价 | `bill_item`（明细表，一行一个商品） |
| 给钱了没有 | `bill.paid`（0 = 赊账，月底记得还） |

**特别注意：** 单子存好了，仓库里真的就有 100 瓶可乐了吗？
按铁律二，**还没有**。这时候它只是"草稿"（`status = DRAFT`）。

### 过账：让这张单真正生效

老板确认没问题，点了"过账"。这时系统一口气做了四件事：

1. 往流水本（`stock_record`）里记一笔：**+100 瓶**
2. 重算可乐的"平均进价"（这个后面 [04](04-数据库与核心算法.md) 会细讲）
3. 因为赊账了，记一笔：**我欠老李 300 块**
4. 自动生成一张**会计凭证**（是的，它还是个正经账房先生）

这四件事**要么全部成功，要么全部失败**。绝不会出现"库存加了、欠款没记"的情况。
代码里管这叫**事务**（`@Transactional`），[02](02-名词翻译.md) 里会解释。

### 上午：卖货

有人来买 5 瓶可乐，卖了 20 块，收现金。这是一张**销售出库单**（`SALE`）。

过账时：

- 流水本记一笔：**−5 瓶**
- 算出这 5 瓶的**成本**（按当前平均进价），记为"结转成本"
- **毛利 = 销售额 − 成本** ← 老板最关心的数字就是这么来的
- 现金多了 20 块

> 如果顾客要赊账卖 20 块没收钱，那就是"挂账"，系统记：**顾客欠我 20 块**。这就是"应收账款"。

### 下午：盘点，发现少了

老板数了一下货架，可乐实际只有 90 瓶，账上却显示 95 瓶，少了 5 瓶（摔碎了、被偷了、记错了）。

这时候用**库存盘点**功能：录入实际数 90，系统自动算出差额 −5，
自动生成一张**报损单**（`LOSS`）并过账。账就对上了。

> 反过来说，如果实际数比账上多，系统就生成**盘盈单**（`GAIN`）。
> 这两个是自动配对的：亏了就叫 LOSS，多了就叫 GAIN。

### 下午：发现上周的单开错了

上周把 100 瓶写成了 10 瓶。怎么办？

**不能删。** 删了账就断了。要做**冲正**：系统复制那张单，
生成一张数量相同、方向相反的"销售退货单"并立刻过账，把库存退回去。
**原来那张错误的单原封不动留在库里**，老板什么时候查都能查到。

### 晚上：看今天赚了多少

打开**经营看板**，看到：今天卖了 800 块，毛利 180 块，毛利率 22.5%，仓库里还有多少钱的货。

这些数字不是存在哪儿的，是**当场把流水加起来算出来的**（铁律一）。

## 二、把这些翻译回代码：软件的六大块

```
现实中的东西              →  代码里叫什么             →  数据库哪张表
────────────────────────────────────────────────────────────────
商品档案（叫啥、多少钱）   →  Product             →  product
仓库（前店/后库）          →  Warehouse           →  warehouse
供应商 / 客户              →  Partner             →  partner
进货卖出的一切单据         →  Bill + BillItem     →  bill / bill_item
每一笔进出的流水账         →  StockRecord         →  stock_record  ★核心
财务凭证                   →  Voucher/VoucherItem →  voucher / voucher_item
```

**中间那列大小写开头的词，就是 Java 类的名字。** 你在 `backend/src/main/java/com/local/erp/entity/`
下面能看到它们一个一个躺在里面，每个类里写的就是这张表有哪些列。

## 三、七种单据类型（记住这张表，代码就看懂一半）

`BillService.java` 最开头写着：

```java
public static final List<String> TYPES = List.of(
    "PURCHASE", "SALE", "PURCHASE_RETURN", "SALE_RETURN", "LOSS", "GAIN", "TRANSFER");
```

翻译成中文：

| 代码里的名字 | 中文 | 库存方向 | 什么时候用 |
|---|---|---|---|
| `PURCHASE` | 采购入库 | **加** | 进货 |
| `SALE` | 销售出库 | **减** | 卖货 |
| `PURCHASE_RETURN` | 采购退货 | **减** | 把货退给供货商 |
| `SALE_RETURN` | 销售退货 | **加** | 顾客把货退回来 |
| `LOSS` | 报损 | **减** | 坏了/丢了/盘点少了 |
| `GAIN` | 盘盈 | **加** | 盘点多了 |
| `TRANSFER` | 调拨 | 一减一加 | 从后库挪到前店 |

**`TRANSFER` 特殊**：它是唯一会写**两条**流水的类型 —— 出仓那条仓库减，入仓那条仓库加。
代码在 `BillService.post` 里单独 `if` 处理它。

### 为什么这么设计，而不是每种单据写一个类？

因为它们的处理流程其实一模一样：**算方向 → 检查库存够不够 → 写流水**。
唯一的差别就是"方向是加还是减"。所以代码用一个 `switch` 就搞定了：

```java
int signed = switch (type) {
    case "PURCHASE", "SALE_RETURN", "GAIN" -> item.getQuantity();      // 正数 = 入库
    case "SALE", "PURCHASE_RETURN", "LOSS" -> -item.getQuantity();     // 负数 = 出库
    default -> throw new IllegalArgumentException("非法类型 " + type);
};
```

> 这就是这个项目写得好的地方：**用"符号"表达"方向"**，几行代码覆盖 6 种业务。

## 四、三条铁律在代码里的样子

### 铁律一：库存是算出来的

`StockService.java` 里短短几行：

```java
public Map<Long, Integer> currentStock() {
    Map<Long, Integer> stock = new HashMap<>();
    for (StockRecord r : recordMapper.selectList(null)) {      // 把所有流水全捞出来
        stock.merge(r.getProductId(), r.getQuantity(), Integer::sum);  // 按商品累加
    }
    return stock;
}
```

翻译成人话：**把流水本从头翻到尾，看见"可乐 +100"就加 100，看见"可乐 −5"就减 5，最后剩下的就是库存。**

所以：

- 想知道库存？→ 看这里
- 库存不对？→ 一定是有哪条流水记错了，去 `stock_record` 表找它
- 想改库存怎么办？→ **不能改数字**，要补一条流水（盘点/报损/盘盈）

### 铁律二：草稿 vs 已过账

`bill` 表有个 `status` 字段，只有两个值：`DRAFT`（草稿）和 `POSTED`（已过账）。

```java
if ("POSTED".equals(bill.getStatus())) throw new IllegalArgumentException("单据已过账，不能重复过账");
```

这行就是防止你把一张单过账两次、库存扣两份。

### 铁律三：冲正

`BillService.reverse()` 方法干的事：

1. 复制原单，类型换成**相反的那一种**（`REVERSE_TYPE` 这张对照表定义了对应关系）
2. 数量、价格照抄
3. 备注写成 `"冲正#原单号"`，方便以后查是谁冲了谁
4. **立刻过账**，反向流水把库存还原
5. 如果原单是赊账的，把它结清（钱不用还了）
6. **原单一字不改地留着**

```java
private static final Map<String, String> REVERSE_TYPE = Map.of(
    "PURCHASE", "PURCHASE_RETURN", "PURCHASE_RETURN", "PURCHASE",
    "SALE", "SALE_RETURN",        "SALE_RETURN",     "SALE",
    "LOSS", "GAIN",               "GAIN",            "LOSS",
    "TRANSFER", "TRANSFER");
```

这行 `Map.of(k1,v1,k2,v2,...)` 读起来就是："A 的反面是 B，B 的反面是 A……"。

另外注意第 3 步的备注，它同时也是一把锁：

```java
if (origin.getRemark() != null && origin.getRemark().startsWith("冲正#"))
    throw new IllegalArgumentException("冲正单不能再冲正");
```

防止你无限套娃：你没法把一张"冲正单"再冲正一次，这样就永远扯不清了。
