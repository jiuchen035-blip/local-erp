# 03 · 从双击到能用：启动流程一步一步拆

> 这一章回答："我双击那个 exe（或 bat）之后，电脑到底做了哪些事？"
> 看懂这一章，任何"起不来"的问题你都能自己定位到第几步断了。

---

## 零、两种运行方式，差别在哪

| | 开发态 | 打包态（发给别人） |
|---|---|---|
| 怎么起 | `start-backend.bat` 或 `java -jar target\xxx.jar` | 双击 `账管卫士.exe` |
| 前端 | Vite 单独跑在 5173 | 静态文件已经打进 jar，同一个 8080 端口出 |
| 数据目录 | `backend/data/` | 程序安装目录里的 `data/` |
| JRE | 用你装的 JDK | exe 自带 JRE（`runtime/`） |

**数据目录这件事是整个项目最讲究的地方**，因为它决定了"我的数据会不会写到奇怪的地方"。

---

## 一、启动时序总览（记住这 8 步）

```
双击 exe / 双击 bat
  │
  ├─ 第 1 步   AppHome.dir()         决定"我的数据放哪"          ← Spring 还没起来
  ├─ 第 2 步   建 data 目录           SQLite 不会自己建文件夹
  ├─ 第 3 步   检查有没有待恢复备份   有就先自动备份当前库，再替换
  ├─ 第 4 步   挑一个空闲端口         8080 被占就让位到 8081…
  │
  ├─ 第 5 步   Spring Boot 启动       读 application.yml、连数据库
  ├─ 第 6 步   schema.sql             18 张表不存在就建
  ├─ 第 7 步   MigrationConfig        老库加字段、补默认数据     ← 幂等，可重复跑
  ├─ 第 8 步   各种 Runner 跑起来     自动备份一次、打开浏览器、挂定时器
  │
  └── 完事，浏览器弹出 http://localhost:8080
```

注意 **第 1~4 步在 Spring 启动之前**。为什么？因为一旦数据库连接建好，你就不能再随便动数据库文件了。
所以"决定路径、建目录、换数据库文件"这些脏活必须在那之前做完。

---

## 二、第 1 步：我的数据放哪（`AppHome.java`）

桌面软件的第一难题：**双击启动时，"当前目录"是不确定的。**
从快捷方式启动、从任务栏启动、从"运行"对话框启动，工作目录可能完全不同。
如果不处理，数据可能一会儿写到桌面，一会儿写到 System32。

`AppHome.resolve()` 用了三级定位：

```java
// 1) 打包工具可能注入的系统属性，直接信
String prop = System.getProperty("app.home");
if (isBlank(prop)) prop = System.getProperty("app.dir");
if (!isBlank(prop)) return new File(prop);

// 2) 扫描 classpath，找到 jar 所在的文件夹；
//    如果这个文件夹里有 .cfg 文件 → 说明是打包运行 → 用这个文件夹
File packaged = packagedJarDir();
if (packaged != null) return packaged;

// 3) 都不是 → 按开发态处理：用当前工作目录
return new File("").getAbsoluteFile();
```

**为什么用"jar 旁边有没有 .cfg"来判断？** 因为 jpackage 打包出来的程序，
一定会在应用目录放一个 `<应用名>.cfg` 启动配置文件。这是最靠谱的"我是打包程序"标志。

> **好处**：数据永远在程序目录里。**删掉整个程序文件夹 = 彻底卸载**，没有残留。

## 三、第 3 步：为什么"恢复备份"要放在这里

备份恢复不能热做（数据库正在用，不能直接覆盖文件）。
所以设计成 **两步走**：

1. 用户在界面点"恢复" → 系统把选中的备份复制成 `data/erp.db.restore-pending`（挂起标记）
2. 用户重启程序 → `ErpApplication.main` 在 **Spring 还没起来** 的时候：
   - 先把当前正在用的库备份成 `backup/pre-restore-<时间戳>.db`（**防止误恢复丢数据**）
   - 再把那个 pending 文件覆盖到 `data/erp.db`
   - 删掉 pending 标记

```java
File pending = new File(dataDir, "erp.db.restore-pending");
if (pending.isFile()) {
    // ① 当前库先自动备份
    Files.copy(db.toPath(), new File(backupDir, "pre-restore-" + ts + ".db").toPath(), REPLACE_EXISTING);
    // ② 替换主库
    Files.copy(pending.toPath(), db.toPath(), REPLACE_EXISTING);
    pending.delete();
}
```

> 这个"破坏性操作前先自动保险"的思路贯穿整个项目（冲正不删原单、安装包不覆盖数据目录）。

## 四、第 4 步：端口被占怎么办

老板电脑上可能已经有个程序占着 8080。所以：

```java
boolean hasExplicitPort = args != null && Arrays.stream(args)
        .anyMatch(a -> a.toLowerCase().startsWith("--server.port"));
if (!hasExplicitPort) {
    String port = pickFreePort("8080", "8081", "8082", "18080");   // 依次试连
    if (port != null) System.setProperty("server.port", port);
}
```

`pickFreePort` 的原理很朴素：**试着绑定这个端口，绑得上就是没人用，绑不上就试下一个。**

> ⚠️ 所以如果你想固定端口，就在启动参数里带 `--server.port=8080`，
> 它看到你自己指定了就不管了。

## 五、第 5 步：`application.yml` 每一行在干什么

```yaml
server:
  port: 8080                        # 监听端口（可能被上面第 4 步改掉）

app:
  auto-open-browser: true           # 启动完自动开浏览器（给 exe 用，命令行跑时挺烦）

logging:
  file:
    name: ${erp.data.root:.}/data/logs/local-erp.log   # 日志写文件。注意这个 ${} 取的就是第 1 步设的值
  logback:
    rollingpolicy:
      max-file-size: 10MB           # 超过就切一个新文件
      max-history: 30               # 最多留 30 个

spring:
  datasource:
    url: jdbc:sqlite:${erp.data.root:.}/data/erp.db    # 数据库文件路径
    driver-class-name: org.sqlite.JDBC
  sql:
    init:
      mode: always                  # 每次启动都跑 schema.sql
      schema-locations: classpath:schema.sql

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true    # 数据库 bill_no ↔ Java billNo 自动对应
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl   # ⚠️ 打印所有 SQL（开发遗留，见下）

ai:
  provider: auto                    # AI 来源模式
  base-url: https://api.deepseek.com/v1
  api-key: "在此填入你的API-KEY"
  model: deepseek-chat
  embedding:
    enabled: false                  # 知识库语义检索开关，默认走关键词检索
```

**几个要注意的点：**

- `${erp.data.root:.}` 的意思是"取这个系统属性，如果没有就用 `.`（当前目录）"
- **MyBatis-Plus 的 SQL 日志在生产也开着**，给商家用时会往外吐 SQL（这是已知问题，见 `代码导读-架构与数据流.md` 故障 #13）
- `map-underscore-to-camel-case` 让你不用手写字段映射，数据库 `bill_no` 自动对应 Java 的 `billNo`
- AI 的这些默认值**会被 UI 保存的设置覆盖**（存在 `data/ai-settings.json`），所以你改 yml 不一定生效

## 六、第 6 步：`schema.sql` 建表

好处是：全部带 `IF NOT EXISTS`，**可以无限次执行**，跑一百遍也不会出错。

```sql
CREATE TABLE IF NOT EXISTS product (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,
    sku         TEXT NOT NULL UNIQUE,
    ...
);
```

几个约定：

| 写法 | 意思 |
|---|---|
| `PRIMARY KEY AUTOINCREMENT` | 主键，自动 +1 |
| `NOT NULL DEFAULT (datetime('now','localtime'))` | 没写就用当前时间 |
| `type TEXT NOT NULL CHECK (type IN (...))` | 只能填括号里这几个值，填别的数据库会拒绝 |
| `REFERENCES bill(id) ON DELETE CASCADE` | 单据删了，它的明细跟着自动删 |

**18 张表**（详见 [04](04-数据库与核心算法.md)）。

## 七、第 7 步：`MigrationConfig` —— 让老版本平滑升级

老板用的是 0.2 版本，你现在发给他 0.6 版本，他的数据不能丢。

问题是 SQLite 不支持 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`。
所以项目的做法是 **"试一下，失败就当已经有了"**：

```java
try { jdbc.execute("ALTER TABLE product ADD COLUMN avg_cost REAL"); } catch (Exception ignored) {}
try { jdbc.execute("ALTER TABLE product ADD COLUMN barcode TEXT"); } catch (Exception ignored) {}
// ... 一共四十多条这样加字段的语句
```

然后补数据、补默认配置：

```java
jdbc.update("UPDATE product SET avg_cost = cost_price WHERE avg_cost IS NULL");  // 均价用成本价初始化
if (仓库表是空的) jdbc.update("INSERT INTO warehouse(name, remark) VALUES('主仓库','默认仓库')");
if (用户表是空的) jdbc.update("INSERT INTO sys_user(...) VALUES('admin', ?, 'ADMIN')", bcrypt密文);
if (知识库空的) kbService.addDocument("系统操作指南", GUIDE, "guide");   // 内置说明书，AI 开箱可用
if (科目表空的) 插入 17 个常用会计科目;
```

**为什么这么写而不是用 Flyway？**
SQLite + 单机场景下，多一个迁移框架多一份出错概率。这种"幂等 + 兜底补齐"的写法，
保证**任何版本的老库都能被新版本启动**，且五十行看懂。

> ⚠️ 已知隐患：`catch (Exception ignored)` 会把"磁盘满了""表被锁了"这类**真失败**也吞掉。
> 真出问题时会表现为"启动了，但某个功能报 no such column"。详见缺陷清单 #11。

## 八、第 8 步：各种 Runner

Spring 起来之后，会自动跑几件事：

| 谁 | 什么时候 | 干什么 |
|---|---|---|
| `BackupService.onStartup`（`@PostConstruct`） | Bean 创建后 | 立刻备份一次 |
| `BackupService.nightly`（`@Scheduled(cron="0 0 23 * * ?")`） | 每晚 23:00 | 再备份一次 |
| `AutoOpenBrowser`（`ApplicationRunner`） | 全部就绪后 | 睡 1.5 秒，用系统浏览器打开首页 |

关于自动备份，用的是 SQLite 独有的命令：

```java
jdbc.execute("VACUUM INTO '" + DIR + "/" + name + "'");
```

`VACUUM INTO` 的好处：**在线热备**。不用停服务，而且导出来的是一个一致性的、整理过碎片的干净副本。
比直接 copy 文件安全得多（copy 可能拷到写了一半的状态）。

最多留 30 份，多的按文件名倒序删掉最老的：

```java
Arrays.stream(files).sorted((a,b) -> b.getName().compareTo(a.getName()))
      .skip(KEEP).forEach(File::delete);
```

## 九、请求进来的第一站：拦截器是怎么挂上的

`WebConfig` 里三行搞定：

```java
@Override
public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(authInterceptor)
            .addPathPatterns("/api/**")              // 所有 /api 开头都要过安检
            .excludePathPatterns("/api/auth/login"); // 但登录本身不用（你还没有手环呢）
}
```

顺便还定义了一个"密码加密器"零件：

```java
@Bean
public PasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(); }
```

**顺带澄清一个很容易误解的地方**：项目引了 Spring Security，但你看 `SecurityConfig`：

```java
http.csrf(c -> c.disable())
    .authorizeHttpRequests(a -> a.anyRequest().permitAll());   // 全部放行
```

意思是：**Spring Security 在这里只被用来做 BCrypt 加密，它的权限拦截能力完全没启用。**
真正的安检是自己写的 `AuthInterceptor`。别答反了。

## 十、常见的"起不来"及其原因

| 现象 | 原因与处理 |
|---|---|
| **双击 exe 报 Failed to launch JVM** | 90% 是没解压就在压缩包里双击了。exe 旁边必须有 `app/` 和 `runtime/` 两个文件夹 |
| 同上，仍未解决 | 用包里的 **`账管卫士-控制台启动.bat`**，它绕过启动器直接跑，会把真实错误显示在黑窗口里 |
| **`mvn spring-boot:run` 报 ClassNotFoundException** | 中文路径下插件生成的 JVM 参数文件编码错乱。**永远用 `java -jar target\xxx.jar`** |
| **改了代码没效果** | ⚠️ 见下方警告 |
| **8080 被占用** | 程序会自动换 8081；想固定就加 `--server.port=18080` |
| **报端口但还是打不开** | 看 `data/logs/local-erp.log` |
| **数据想从头来** | 停掉程序，删掉 `data` 文件夹，重启即可全部重置 |

> ### ⚠️ 一个你现在就踩得到的坑
>
> `start-backend.bat` 里写死的是：
> ```bat
> if not exist "target\local-erp-0.5.0.jar" ( ...打包... )
> "%JAVA_CMD%" -jar target\local-erp-0.5.0.jar
> ```
> 但 `backend/pom.xml` 里版本号已经是 **0.6.0**，`target/` 里也已经有 `local-erp-0.6.0.jar`。
> 结果：**你改完代码用这个 bat 启动，跑的还是旧的 0.5.0 的 jar，改的东西一点没生效。**
>
> 正确做法（开发时）：
> ```bat
> cd backend
> C:\Users\ZhuanZ\erp-tools\apache-maven-3.9.16\bin\mvn.cmd -DskipTests package
> java -jar target\local-erp-0.6.0.jar
> ```
> 或者干脆把 bat 里的 `0.5.0` 改成 `0.6.0`（这是你接手后建议第一时间改的地方）。

## 十一、想验证"启动流程"是否正常，看这几处

1. 控制台出现 `Started ErpApplication in x.x seconds` → Spring 起来了
2. `data/` 目录下出现了 `erp.db`、 `logs/`、`images/`、`ai-settings.json`
3. `backup/` 里多了一个 `erp-日期.db` → 启动自动备份生效了
4. 浏览器自动打开且能登录 `admin / admin123` → 全都正常

> **第一次登录后请立刻改密码**：内置管理员账号 `admin / admin123` 是写在代码里的公开信息。
