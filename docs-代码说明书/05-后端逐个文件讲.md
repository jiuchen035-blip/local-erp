## 二、24 个 Controller（服务员）都在干什么

> **记住一条铁律：Controller 里不许写业务逻辑。** 它只做三件事：接收、调用 Service、包装返回值。

### 一个典型的 Controller 长什么样

拿 `BillController` 举例（30 行就完事了）：

```java
@RestController                          // 我是服务员
@RequestMapping("/api/bills")            // 我管这个地址开头的所有事
@RequiredArgsConstructor                 // 管家帮我把 Service 塞进来
public class BillController {

    private final BillService billService;
    private final BillMapper billMapper;
    // ...

    @GetMapping                                        // GET /api/bills
    public List<Bill> list(@RequestParam(required = false) String status,
                           @RequestParam(required = false) String type) {
        LambdaQueryWrapper<Bill> qw = new LambdaQueryWrapper<Bill>()
                .orderByDesc(Bill::getId).last("limit 200");   // 最多给 200 条
        if (status != null && !status.isBlank()) qw.eq(Bill::getStatus, status);
        if (type != null && !type.isBlank()) qw.eq(Bill::getType, type);
        return billMapper.selectList(qw);
    }

    @PostMapping("/{id}/post")                         // POST /api/bills/123/post
    public Map<String, Object> post(@PathVariable Long id) {
        Bill bill = billService.post(id);              // 真正的活交给厨师
        return Map.of("message", "单据 " + bill.getBillNo() + " 已过账", "billNo", bill.getBillNo());
    }
}
```

**注意三个细节：**

1. **返回值是 `Map.of(...)` 或对象**，从来不自造 JSON 字符串 —— Jackson 会帮你序列化
2. **用 `LinkedHashMap` 而不是 `HashMap`** 的时候，是为了让字段在 JSON 里保持你放进去的顺序
3. `.last("limit 200")` 是防失控：再大的表也不至于一次拉几十万行

## 三、Service（厨师）逐个讲

### 🥇 BillService —— 全系统的心脏

**四个方法就是整个业务：**

| 方法 | 干什么 | 什么时候被调用 |
|---|---|---|
| `createDraft(dto, user)` | 校验 + 存草稿。**不动库存** | 界面点"保存"、AI 生成草稿 |
| `post(billId)` | 过账。检查库存 → 写流水 → 重算成本 → 置 POSTED → 生成凭证 | 界面点"过账"、冲正时内部调用 |
| `reverse(billId)` | 冲正。生成反向单并立刻过账 | 界面点"冲正" |
| `detail(billId)` | 拼一个给前端看的数据结构（含商品名、仓库名、往来单位名） | 点开单据详情/打印 |

**单据编号怎么来的**（`nextBillNo`）：

```java
String prefix = "DJ" + 当天日期 + "-";        // DJ20260912-
// 查出当天最大的那个单号
String max = billMapper.selectList(new LambdaQueryWrapper<Bill>()
        .likeRight(Bill::getBillNo, prefix)    // bill_no LIKE 'DJ20260912-%'
        .orderByDesc(Bill::getBillNo)
        .last("limit 1")).stream().findFirst().map(Bill::getBillNo).orElse(null);
int seq = max == null ? 1 : 截取末段数字 + 1;
return prefix + String.format("%04d", seq);   // DJ20260912-0001
```

> **为什么用"查最大 +1"而不是"数有几条 +1"？**
> 因为删过单。数条数会撞号（删了 0003，下一条又生成 0003，而 0003 的历史记录还在）。
> 这种细节是踩过坑才写得出来的。

**⚠️ 已知问题**：这个方法没有 `@Transactional`（详见 `代码导读` 故障 #4），
同类或极端的并发下可能撞号。这是你接手后可以改的第一个地方。

### 🥈 StockService —— 库存与货源

三件事：

1. `currentStock()` / `stockByWarehouse()` —— 把流水加起来算库存（见第 04 章）
2. `lowStock()` —— 库存预警

```java
.filter(p -> nzI(p.getNoAlert()) == 0)        // 标了"不监控"的跳过（同行调货的一次性商品）
.filter(p -> {
    int cur = stock.getOrDefault(p.getId(), 0);
    int safe = nzI(p.getSafeStock());
    return safe > 0 ? cur < safe : cur <= 0;  // 设了安全库存就比它，没设就看是不是<=0
})
```

> 这个"安全库存为 0 时按缺货算"的设计很体贴：老板懒得给每个商品设安全库存，
> 那就至少在彻底卖光的时候提醒他。

3. `peerSources()` —— 同行货源台账。把带供应商的采购流水按 **供应商 × 商品** 聚合，
   输出"从老李那儿最后一次进价多少、进过多少、最近什么时候"。这是个小而妙的报表：

```java
String key = r.getPartnerId() + ":" + r.getProductId();   // 用字符串当复合主键，简单粗暴
Agg a = agg.get(key);
if (a == null) { a = new Agg(); agg.put(key, a); ... }
if (cur.compareTo(a.lastTime) > 0) { a.lastTime = cur; a.lastPrice = r.getPrice(); }
a.totalQty += r.getQuantity();
```

### 🥉 VoucherService —— 账房先生

**在 `BillService.post` 的同一个事务里被调用**（很重要，所以凭证和库存永远一致）。

职责：根据单据类型自动编出一张凭证。核心是一张科目对照表：

| 业务 | 借方 | 贷方 |
|---|---|---|
| 销售（现结） | 1001 库存现金 | 6001 主营业务收入 |
| 销售（挂账） | 1122 应收账款 | 6001 主营业务收入 |
| 销售还要结转成本 | 6401 主营业务成本 | 1405 库存商品 |
| 采购（现结） | 1405 库存商品 | 1001 库存现金 |
| 采购（挂账） | 1405 库存商品 | 2202 应付账款 |
| **调拨** | **不生成**（只是换仓，没有价值移动） | |

代码开头第一行就 return：

```java
if ("TRANSFER".equals(bill.getType())) return;
```

> 手工凭证也走这里，保存时强制检查"借方合计 = 贷方合计"，不平就报错 —— 这是会计的基本常识，
> 但代码里手工校验一遍能挡住 99% 的错误录入。

### 其它 Service

| Service | 一句话 | 有意思的地方 |
|---|---|---|
| **KbService** | 知识库：切块 + 检索 | 检索有两种模式（见下）；向量失败自动降级关键词 |
| **BackupService** | 自动备份 | `VACUUM INTO` 热备；恢复是"挂起 + 重启生效" |
| **IntegrationService** | 电商订单导入 | **逐单独立事务**，一单失败不影响其它；自动建档的商品成本=售价（毛利记 0，不虚报） |
| **ProductCodeService** | SKU 自动生成 | 分类名取拼音首字母（TinyPinyin）+ 分类序号 + 最大序号 |
| **FinanceSettingsService** | 计税开关/默认税率 | 一个全局单例设置，被 BillService 和 VoucherService 读 |
| **ShopInfoService** | 打印抬头 | 店铺名/地址，打印时套在单据最上面 |

#### KbService 的检索双模式（值得单独说）

```java
if (embeddingClient.isVectorMode()) {
    try {
        double[] qv = embeddingClient.embed(List.of(query)).get(0);   // 把问题变成一串数字
        for (KbChunk c : all) {
            if (c.getEmbedding() == null) continue;
            double[] cv = parseEmbedding(c.getEmbedding());
            scored.add(buildHit(titles, c, cosine(qv, cv)));          // 算余弦相似度
        }
    } catch (Exception e) {
        log.warn("向量检索失败，降级关键词: {}", e.getMessage());
        keywordScore(scored, titles, all, query);                     // 兜底！
    }
} else {
    keywordScore(scored, titles, all, query);
}
```

**为什么做两套？** 因为语义检索需要额外配一个 embedding 模型（要钱或者麻烦）。
作者希望**零配置也能用**，所以默认走中文关键词：

```java
for (String term : query.split("[\\s，。？！、,.?!:：]+")) {
    grams.add(term);                                     // 整词
    for (int i = 0; i + 2 <= term.length(); i++) grams.add(term.substring(i, i + 2));  // 2-gram 滑窗
}
```

中文没有空格，怎么分词？简单粗暴：**每两个字一组滑过去**。
"怎么冲正单据" 会被切成 "怎么/么冲/冲正/正单/单据"，其中"冲正"能命中目标文本。
粗糙但有效，而且**零依赖、零配置**。这就是"够用就行"的工程判断。

## 四、config 包：规则都在这

### AuthInterceptor —— 每个请求的安检门

```java
public boolean preHandle(...) {
    if ("OPTIONS".equalsIgnoreCase(request.getMethod())) return true;   // 预检请求直接放行
    if (request.getRequestURI().startsWith("/api/images/")) return true; // 图片不需要登录

    SessionUser user = tokenStore.get(request.getHeader("X-Auth-Token"));
    if (user == null) { 401; return false; }       // 没手环
    CURRENT.set(user);                              // 记到 ThreadLocal，业务代码随时能取

    if (!AccessRules.allow(user.getRole(), uri, method)) { 403; return false; }  // 权限不够

    if ("POST".equals(method) || "PUT".equals(method) || "DELETE".equals(method)) {
        // 写操作自动记日志
        opLogMapper.insert(log);
    }
    return true;
}
```

> **为什么图片要放行？** 因为 HTML 的 `<img src="...">` 是浏览器自动发的请求，
> 你没法给它加自定义请求头。**这是前端和后端妥协的结果。**

### AccessRules —— 权限的唯一事实来源

```java
public static final List<String> ADMIN_PREFIXES = List.of("/api/users", "/api/system", "/api/finance", "/api/integrations");
public static final List<String> ADMIN_METHODS = List.of("DELETE");

public static boolean allow(String role, String uri, String method) {
    if ("ADMIN".equals(role)) return true;
    if (ADMIN_METHODS.contains(method.toUpperCase())) return false;
    return ADMIN_PREFIXES.stream().noneMatch(uri::startsWith);
}
```

**为什么单独抽一个类？** 因为 **AI 工具层也要用同一套规则**：

```java
if (!factory.isAdmin() && needAdmin.containsKey(name)) {
    if (!AccessRules.allowTool(role, true)) return Map.of("error", AccessRules.denyReason(role, true));
}
```

这保证了：**AI 不可能比登录用户拥有更大的权力**。这叫"操作平权"，是这套 AI 设计里最值得夸的一点。

### GlobalExceptionHandler —— 错误翻译官

```java
@ExceptionHandler(IllegalArgumentException.class)  → 400 {"error": "业务提示原文"}
@ExceptionHandler(SecurityException.class)         → 403 {"error": "..."}
@ExceptionHandler(Exception.class)                 → 500 {"error": "服务器内部错误：..."} + 记日志
```

> **约定**：业务上"不允许"，就 `throw new IllegalArgumentException("人话")`，
> 这句话会原样出现在用户屏幕上。**不要返回错误码让前端去翻译。**

## 五、Entity 和 Mapper：最没技术含量但最多的文件

### Entity 长什么样

以 `Product` 为例，20 个字段，每个字段上面的注释就是数据库那一列的含义：

```java
@Data                       // Lombok：自动生成所有 getter/setter
@TableName("product")       // 对应哪张表
public class Product {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
    private String sku;
    private Double salePrice;      // ← Java 里叫 salePrice，数据库里叫 sale_price
    private Double avgCost;        // ← 移动加权平均成本
    private Integer noAlert;       // ← 1 = 不监控库存预警
    // ...
}
```

`@Data` 让你不用写 40 个 getter/setter。这是这个项目能这么短的原因之一。

### Mapper 长什么样

```java
@Mapper
public interface ProductMapper extends BaseMapper<Product> {
    // 空的！
}
```

**空的？对。** 因为继承了 MyBatis-Plus 的 `BaseMapper`，增删改查方法全部免费获得：

```java
productMapper.selectById(1L);        // 查一个
productMapper.selectList(条件);       // 查列表
productMapper.insert(p);             // 插入（自动把生成的主键回填到 p.id）
productMapper.updateById(p);         // 按主键更新
productMapper.deleteById(1L);        // 删除
```

> **想加一个字段，只需要改 Entity 里的字段 + 加一句 ALTER TABLE 迁移。** 不用动任何 XML。

## 六、一个完整请求的旅程（串起来）

场景：老板在"进货/销售"页面点"保存并过账"一张采购单。

```
① 浏览器  POST /api/bills  {"type":"PURCHASE", "items":[...]}
          header: X-Auth-Token: abc123
   ↓
② axios 拦截器（api.js）自动带上 token
   ↓
③ Vite proxy（开发态）/ 同源（打包态）把请求送到 8080
   ↓
④ AuthInterceptor.preHandle：查 token → 存 ThreadLocal → 检查权限 → 记 op_log
   ↓
⑤ BillController.create(@RequestBody BillDto dto)
      Jackson 把 JSON 变成 BillDto 对象
      dto.getAutoPost() == true 时顺便调用 post()
   ↓
⑥ BillService.createDraft(dto, "张三")
      校验类型合法、有明细、有仓库、调拨要有目标仓库
      生成单号 → insert bill → 逐行 insert bill_item → 算总额 → update bill
   ↓
⑦ BillService.post(bill.getId())   ← @Transactional 开始
      StockService.stockByWarehouse()  → 拉全部流水算当前库存快照
      逐行：
        计算折后价 effPrice
        计算方向 signed（采购是正数）
        检查庫存（出库类才检查）
        采购 → 重算移动加权平均成本 → 更新 product.avg_cost
        insertRecord → insert stock_record（单价、成本快照、仓号、是否挂账全带上）
      bill.status = POSTED
      BillService 的同一事务里调用 VoucherService.createFromBill(bill)
        → insert voucher + voucher_item
   ↓  <- 事务提交
⑧ 一路返回 Map.of("id",..., "billNo",..., "total",...)
   ↓
⑨ GlobalExceptionHandler（如果中途抛了异常，在这儿被翻译成 {"error":"..."}）
   ↓
⑩ 前端拿到 JSON → Orders.vue 显示"已过账" → 重新拉列表
```

## 七、写新代码时要遵守的规矩

| 规矩 | 原因 |
|---|---|
| Controller 不写业务，只调用 Service | 换界面、加小程序端时不用重写 |
| 会改多处数据的方法加 `@Transactional` | 防止"扣了库存没记欠款"这种脏数据 |
| 业务校验用 `throw new IllegalArgumentException("人话")` | 前端直接显示这段话给用户 |
| 返回给前端用 `LinkedHashMap` | 保证 JSON 字段顺序稳定，便于查看 |
| Entity 用 `@Data`，Mapper 继承 `BaseMapper` | 少写几百行样板代码 |
| 需要判断方向时用正负号，不要写一堆 if | 见 `BillService.post` 的 switch |
| 列表接口加 `.last("limit 200")` 之类的上限 | 防止一次拉爆内存 |
| 权限判断走 `AccessRules`，不要自己写 if | HTTP 和 AI 保持一致 |

> **加一个新 Service 的完整步骤**（记住这个套路，你就能加任何功能）：
> 1. 需要新表 → 在 `schema.sql` 加 `CREATE TABLE IF NOT EXISTS`
> 2. 需要新字段 → 在 `MigrationConfig` 加一句 `try { ALTER TABLE ... } catch {}`
> 3. 加 `XxxEntity` 类
